# 单词首次点击发音

状态：候选修复已实现，生产发布及真实 Safari 听音待验证。

用户在 20261013T190024 上确认发音恢复，但每换一个单词都要点两次，第一次等待也不会发声。前版把预备好的录音交给原生播放器，冷录音仍走 Web Audio；恢复/解码失败只保存录音并提示再次点击。这不能满足首次点击的目标。原设备未采集日志，因此不宣称确定了唯一 Safari 底层原因。

冷加载现在在点击回调内以原生播放器播放短小的零采样 WAV（元素不静音，录音本身无声），下载期间保留该通道。录音返回后更换同一个元素的源并播放，沿用本次手势赋予该元素的授权；不再依赖 Web Audio 恢复/解码成功，也不换另一个未授权播放器。已预加载的音频仍直接在点击内播放。网络/权限真正失败时保留明确提示及相同录音重试，不额外合成，不替换口音或音标。

静默预加载、稳定英美音标签、准备期间重复点击保留意图、跨行独占、切词/离页取消晚到请求、Blob 回收保持。预解码的 Web Audio 缓存被统一原生路径取代；后台不会启动任何播放器。替换无声片段的异步 pause 事件必须检查当前 paused 状态，不能误取消已经开始的新词。

复现检查：将原生产组件放入真实 MP3、生产 CSP 和严格逐元素手势检查的浏览器环境，在 Web Audio 不可用时只点一次，16秒后仍无 ended，界面提示再点一次；这证明旧路径存在首次手势丢失，不能代替用户 Mac 的原始日志。新代码的行为回归覆盖连续三个新词各点一次、无 Web Audio、准备中不显示正在播放、原元素复用、迟到/后台取消、真实权限拒绝重试不重复请求，以及互斥、音标身份、静默预加载和重播。

真实浏览器矩阵覆盖冷/预加载、Web Audio 缺失或拒绝/挂起/解码失败、6.2秒慢下载、后台返回；每项检查英美音、重播和另外两个新词的首次单击。三引擎 CI 使用真实 MP3 与生产 CSP。严格逐元素手势检查属于受控复现条件；真实媒体仍由浏览器解码播放，不用模拟 ended 冒充成功。

参考：[WebKit 的逐元素播放授权说明](https://webkit.org/blog/7734/auto-play-policy-changes-for-macos/)。自动化引擎不等同于 Mac/iOS Safari 真机；最终应在默认停止播放含声音媒体的设置下刷新，逐词只点一次确认实际听音。
