## 用户确认的目标

信源应因文章实质质量、推广性质或明确产品规则而筛选；抓取、提取、图片和模型服务故障不等于内容不合格。时事、科学、文化、商业每天各至少 14 篇，不设单板块或总量上限。数量达标永远不是停止条件；仍保留每日 ¥1.50、240 次尝试、120 分钟处理时间，未完成工作持久保留。

## 发现与修复

- a16z 的原问题已在上一版修复：Substack 的 newsletter-post 正文祖先误中通用 newsletter 删除规则，完整正文被一起移除；跨 a16z 与 One Useful Thing 八篇复现。不是本次反爬或 JavaScript 未加载。严格结构保护与缺失正文拒绝页尾回退已验证。
- 10 月 1–6 日，356 个批次共记录 414 次跳过事件，包含重复尝试；245 次为“正文不足 401 词”，31 次配图不可读，16 次无可用图片，8 次网页读取失败，6 次 JSON 格式错误。旧记录混合了内容判断与技术问题，不能从“跳过”统计推断文章质量。
- 当前生产网络抽查 25 个已启用且已验证来源的订阅，本轮全部取得有效条目。只证明订阅读取，不代表所有文章正文均可读取。
- 两篇 CNBC 短文重新取得 HTTP 200、分别约 379 和 367 个英文词，正文提取没有明显只剩页尾的现象。未经原文逐段核实，短提取结果在新规则中保留检查，不直接称为坏文章。
- 取消 Top-N 标题和标题相似度的预先淘汰；独立分析/研究型榜单进入完整审核。集成审核图片容量从 12 调整为 24，匹配提取层，保留全部图片、30 MB 安全下载边界与成本预留；过大任务不自动放行。
- 各板块最低 14、无上限；取消达到 60 和达到分布后 ¥1 的提前停止。分类缺口影响排序，不排除其他来源。有待处理文章的来源不受旧每轮六次访问数挡住；总尝试和处理时间仍有限。
- 每小时分批读取订阅、先保存 URL 再审稿；当天审稿关闭后及凌晨仍继续收集。等待审核、技术重试、需要检查、内容未入选、规则跳过、已入候选各自可追踪。未知异常归技术问题；1 小时、6 小时退避后，三次失败转需检查，不自动拒绝。不完整/污染正文/孤立图注保持检查状态。未解决记录不随 RSS 翻页过期；后台支持重新入队。
