# Context Reader 首页重设计访谈答案档案

这份文件保存结构化访谈中的用户选择与关键补充，避免对话压缩后只剩摘要。它是证据档案，不是当前实现指令。当前有效结论请先读 `docs/home-redesign-current-decisions.md`；详细实现边界请读 `docs/home-v2-implementation-contract.md`。

- 后续答案可以覆盖前文，覆盖关系写入当前决策总表。

## 问卷前的核心体验判断与审美原话

- 用户喜欢现有五彩 Ballpit 球体自由碰撞，认为作为封面或品牌 IP 很吸引人；也喜欢鼠标移动时字母飘出的效果和现有封面按钮的悬停反馈。
- 用户认为开发者的话真诚，适合放入重新编排的使用说明。
- 用户不满意书籍式翻页：真实阅读不是书本翻页场景，速度慢，滚轮究竟负责页面滚动还是翻页存在根本冲突。封面可以保留，封面和内页翻页必须舍弃。
- 用户认为旧主页产生双重失败：视觉已经花哨到影响使用，却又缺少足够连贯、惊艳的动效，整体仍显静态和不够大气。
- 用户对旧 Menu 的悬停语言大体认可，但觉得整体关系奇怪；透明背景使悬停文字看不清；不是所有功能都应塞进 Menu；Reader 也必须保留全站导航能力。
- 用户曾在“书籍封面与后续非书籍内容割裂”“全屏球体碰撞也奇怪”之间犹豫，最终把封面定义为品牌门面而不是实体书。
- 用户反复强调最初初心：像搜索入口一样，打开网站就能复制正文或粘贴网址开始读长文章。后来精选外刊成为同等重要的第二条入口，为没有资源的用户提供文章。
- 用户喜欢 I Read World 的 UI 简洁、清晰，但明确说明这不代表要求 Context Reader 模仿。
- 用户提供两段 Lusion 录屏，要求仔细分析并尽可能完整复刻：图片悬停时文字与图像的 3D 反应、滚动后图片出现的速度形变、点击图片后的共享转场。Context Reader 图片应更小，但动效强度不能因此变弱。
- 用户担心 AI 无法完全理解难以用语言描述的动效，也担心实现者只看代码和构建而没有真正看网站。协作边界因此改为：录屏、截图或网址可作为规格；Codex 先拆关键帧和不确定项，完成真实浏览器自检，但复杂视觉最终仍由用户验收。
- 用户多次大调 UI 后发现描述与成品可能天壤之别，反复修改会消耗大量额度并挤压功能和体验投入。因此不再整页开盲盒，而是先持续访谈，再用真实 `/home-v2` 的小切片逐步实现和验收。
- 用户担心讨论过长导致旧决定失效，要求长期记录 UI、功能、基础设施和重要产品决定，并希望产品彻底完成时能回看完整历程。

## 产品重设计决策稿（问题 1–20）

1. 首页承诺：用户否定“把你想读的外刊，变成真正读得下去的英语”这类直白文案，要求仍以语境翻译为主体，所有首页文案需继续斟酌和把关。
2. “我有文章”和“我需要文章”：同一产品的两扇门，首页并列出现。
3. 长期留存：语境解释与划词理解；精选外刊与持续更新；保存文章、进度和跨设备；生词本、复习与 Anki；全文翻译与摘要；难度、兴趣和历史驱动的推荐。
4. 封面：编辑式品牌门面，不再暗示实体书；具体构图和素材仍需看图选择。
5. 新用户第一屏：先看到精选外刊，自主输入作为后续入口。
6. 老用户：只有登录用户才算老用户，优先进入继续阅读、粘贴文章、输入网址组成的工作台，封面缩成品牌标识。
7. 首页动效预算：集中在点击封面后内容快速而有层次地展开；转场必须不普通，并先提供方案选择。
8. 板块名称：精选外刊。
9. 内容规模：少而精，每周稳定更新，人工选题和封面。
10. 内容来源：公共领域、开放许可、获得授权的全文；或只提供简介、难度、原文链接，让用户自行导入正文。
11. 划词案例：在使用说明中用用户主动查看的短动图解释，不单独占首页主段落。
12. 高频入口：输入文章、单独查词、生词本、我的文章放左边。
13. Menu 低频内容：账户与用量、使用说明、意见反馈、设置与无障碍、Admin；开发者的话放入使用说明；意见反馈也出现在首页末段；未登录用户能从 Menu 登录。
14. Reader 导航：暂时全站统一保留左侧高频能力。
15. Menu 悬停：需继续调研优秀案例。
16. Menu 与浮层可读性：需继续调研案例。
17. 第一阶段证明：新老用户都能在几秒内进入真实阅读。
18. 重点风险：描述与实现差距大；功能回归；一次惊艳但长期烦或慢；外刊版权与运营负担；长讨论使旧决定失效。
19. 产品初心：用户遇到长文章时可以复制正文或粘贴网址简便阅读；外刊成为并重特色。
20. 首页暂定顺序：封面后是 Lusion 语言的精选外刊；随后自主导入正文或网址；再用图片或其他方式简要介绍外刊资源、自主导入、语境理解、长文阅读、生词本、保存与 Anki；最后联系、微信与意见反馈。所有文案继续把关。

## 本轮视觉选择（结构 1–6）

1. 新用户封面：完整门面，精选外刊从底部露出一线。
2. 封面转场：球幕开孔，球体让出通道，外刊从封面内部出现。
3. 全站左侧导航：当时选择四个高频入口常驻、Menu 打开不透明抽屉，后续被“悬停胶囊唤出覆盖栏”覆盖。
4. 高频入口：悬停只显示短提示，点击打开真实功能；Menu 所有内容点击打开。
5. 第一屏主句：“在语境里，读懂英文。”
6. 补充：球幕开孔必须证明能真实实现；Menu 项目进入新界面或弹窗仍待斟酌；Reader 左边栏必须保留。

## 全站外壳补充选择

1. Menu 结果：接受混合分流，长内容进入主工作区、短任务使用对话框、设置使用抽屉、Admin 独立路由。
2. Reader 左栏：当时选择固定紧凑左栏，后续被“默认收起、悬停或把手唤出覆盖栏”覆盖。
3. Reader 抽屉：临时覆盖 Reader 左侧，正文不重排，关闭后滚动位置不变。
4. Reader 高频入口：导入切换到保留当前会话的导入工作区；查词聚焦 Reader 右栏；生词本和我的文章使用可关闭工作层覆盖。
5. 球幕补充：球体一开始自由碰撞；下滑时从实时当前位置散开，速度稍慢；外刊列表逐渐上移并承接 Lusion 滚动效果；列表完全移上来时球体才消失。图片使用正常比例并留侧边空间。
6. 导航补充：左栏项目静止时用短名称，悬停显示完整解释并轻微放大；Menu 留在右上并暂时保持现有打开界面。新用户不直接显示整条左栏，悬停现有 `Context Reader` 胶囊后展开；胶囊点击回首页。

## 首页与全站外壳收口选择（问题 1–8）

1. 第一次下滑后自动播完球幕时间轴。
2. 转场未完成时向上滚动，从当前进度自然反向。
3. 点击触发目标约 1.4–1.8 秒，能看清又不拖沓。
4. 当时选择精选外刊双列、6 篇、4:3，后续被“主推全宽 + 三列约 10 篇”覆盖。
5. 外刊类型切换位于标题下方的横向文字分类。
6. 悬停品牌胶囊展开侧栏，点击胶囊回首页。
7. 左栏已有高频入口后，Menu 不重复，只保留低频与账户内容。
8. Reader 导入新文章后，新文章在当前 Reader 打开；返回可恢复旧文章原位置。

## 导航形态 02（问题 9–13）

9. 手机品牌胶囊仍返回首页，另设侧栏按钮。
10. 手机侧栏按钮使用较小的左边缘把手；封面前段可以不露出，滚到自主导入附近再出现。两行品牌按钮的想法随后被否决。
11. 手机侧栏约 70% 宽，但希望再窄一点。
12. 桌面侧栏为更窄的整高覆盖栏；按钮只写三四个字，解释只在悬停时显示。
13. 四个高频入口就是四个小按钮，悬停文字说明并且点击有效，不做复杂信息层级。

## 封面与第一屏 03（问题 14–18）

14. 桌面封面：留白门面，球幕为中央主景，文案偏左克制出现；只确认结构。
15. Ballpit：无明显边框的中心球场，以留白形成范围；用户担心硬边界妨碍散球，背景纯白或极淡背景仍待选择。
16. 第一屏：主句 + 一句克制说明 + 一个进入动作；问卷里“文章”掉到第二行不是用户要的排版。
17. 手机品牌按钮：单行横向胶囊，缩字号和左右留白；两行按钮显得臃肿，不采用。
18. 手机左边缘把手：进入自主导入板块时出现，之后在 Reader 持续保留。

## 精选外刊 04（问题 19–24）

19. 图片相对 Lusion 明显缩小，一屏看见更多文章；缩小不能削弱 3D 表面或共享转场。
20. 当时选择一期一篇主推、其余较小双列；补充要求整个外刊区约两屏、每行三个，后续由问题 25–26 完成覆盖。
21. 图片下方默认信息：标题、刊物来源、难度或阅读时长。
22. 悬停 3D：首版完整复刻录屏强度，再用真实体验判断。
23. 点击色场：从封面自动提取低饱和主色。
24. Reader 第一帧：封面缩成 Reader 顶部小图，再显现标题与正文；后续明确小图是持久文章头图。

## 外刊布局与转场 05（问题 25–30）

25. 主推独占第一行全宽，下一行开始每行三篇。
26. 桌面约 10 篇：1 个主推 + 3 个完整三列标准行；只要一行出现就必须显示满三篇。
27. 分类在同一网格原位置替换，数量相近；不是自由重排或追加。默认先显示推荐，再是不同类别。
28. 手机主推全宽，其余文章两列，数量可稍少。
29. 手机一次点按直接启动共享图片转场并进入 Reader。
30. 当时暂定每次完整播放约 1.8–2.0 秒；后续覆盖为游客完整反向、登录用户压缩反向。无论手机或电脑，Reader 左上都能回到打开文章前的外刊界面。
31. 整组补充：游客只看约两屏的首页精选；Admin 必须能控制默认推荐和每个类别对游客显示哪些文章；登录用户可通过“显示更多”继续看全部库存。

## Reader 返回与外刊库 06（问题 31–36）

31. 不新增问卷里的返回按钮样式。复用当前 Reader 已有的返回首页按钮，只把返回目标改为打开文章时的来源界面。
32. 游客使用完整反向共享转场；登录用户使用压缩部分时间的版本以提高效率，但压缩效果必须真实体验。
33. 封面一直保留在文章顶部，像公众号文章头图；随正文自然滚动，也便于反向共享转场。
34. 登录用户点击“显示更多”后，在当前首页向下展开全部库存；不显示“完整外刊库”标题。外刊是登录用户首页最后一段，页面长可以接受。
35. 登录用户展开区首版筛选：分类 + 难度 + 搜索。
36. Admin：首页分类标签页 + 可拖拽槽位，首槽固定为主推。

## 自主导入与功能介绍 07（问题 37–44）

状态：已回答并归档；只确认结构与流程，不代表接受问卷草图、候选短句或最终 UI。

37. 外刊到自主导入：选择 A，用一句克制的桥接语和明显留白承接，再出现导入器；视觉和文案另做。
38. 正文与网址：选择 A，一个智能入口自动识别网址或正文，长文本粘贴后输入区自动展开；视觉另做。
39. 进入 Reader：选择 C，正文直接进入 Reader，网址导入先预览后确认。网址抓取入口附近增加一个小问号，悬停显示很短的抓取边界说明，并用蓝色或其他强调色提示有些网址不能抓取；正式措辞仍待把关。
40. 默认密度：选择 A，默认紧凑，聚焦或粘贴长正文后平滑展开；但用户明确认为问题描述不够清楚，不确定这是否是“老用户窗口”。纠偏结论：新用户与老用户除顺序和上下文外，导入器 UI 应基本一致；紧凑展开方案只暂定，必须看真实视觉后再确认。
41. 功能介绍主视觉：选择 B，三个不同构图的功能章节，分别讲“读懂、读完、留下”。补充：用卡片表达，并认真设计滚动带来的覆盖、移动等效果；React Bits 可能存在相关参考。这里不是三张普通静态卡片，也没有接受任何具体组件外观。
42. 功能顺序：选择 C，先外刊资源，再自主导入，最后集中说明阅读与学习工具。用户当前明确的全页顺序是“封面 → 外刊 → 导入文章 → 功能介绍 → 反馈、加微信等”，以此覆盖含混的旧回忆。
43. 第一视觉层：选择语境划词解释与翻译、全文翻译与摘要、精选外刊与分类、正文与网址自主导入、生词本与原句积累、Anki 协作、跨设备同步。保存文章与阅读进度没有被选择进入第一层，但没有被授权删除。用户认为普通用户可能不熟悉 Anki，认可“与 Anki 协作”的说法，但正式表达必须让人理解它如何帮助把阅读中的词真正用于记忆。
44. 登录能力：选择 A，正常展示完整能力，只在受限功能旁用极短标记说明登录后可用；视觉与文案另做。

## 全站 Menu 与侧栏 08（问题 45–52）

状态：已回答并归档；最新整组补充覆盖同轮较早选项以及第 06 轮冲突结论。只确认结构和语义，不代表接受问卷草图或最终 UI。

45. 桌面展开与收起：选择 A，品牌胶囊悬停/聚焦后，鼠标能沿连续安全区进入四个入口，完全离开后短延迟收起。随后补充覆盖“整栏”外观：首页桌面端不再展开一块栏面，只让四个按钮悬浮出现，但仍必须保留连续可达的安全区，保证鼠标能够移入并点击。
46. 四个入口：选择 A，简洁小图标 + 二至四字短标签，悬停/聚焦时显示完整解释；图标可以简洁设计，具体图形与视觉另做。按钮保留当前网站已有的出现动效与悬停反馈语言。
47. 功能过渡：选择 A，点击从按钮位置发起同一段短过渡，再按照任务落入不同工作表面；具体动效另做。
48. Reader 左上语义：问卷中先选择 A，但随后两次补充将其覆盖。Reader 不再显示 `Context Reader` 品牌胶囊，也不再用悬停唤出高频入口；现有布局位置只保留“回到首页”按钮，点击直接回到彩球碰撞封面。四个高频按钮作为独立固定操作始终显示，其位置不能默认挤在回首页按钮旁，需用真实 Reader 视觉稿确认。
49. 桌面 Menu 主外壳：选择 B，右上按钮下方使用紧凑浮层。因为首页左侧已有悬浮高频按钮，Menu 不再做另一条整栏；除外壳改为浮层外，现有动效语言可以先保留，尺寸与视觉另做。
50. Menu 内容：选择 B，悬停只高亮项目，点击后详情不跳往新页面，而在 Menu 的同一套浮层关系中替换或向左展开内容承载区。用户把展开后的左侧大块视作 Menu 自己的“页面”。是否完全不透明不先冻结，但文字、按钮和内容必须清晰可读。
51. Menu 顺序：选择 A，顶部先显示登录或当前账户身份，其后依次为使用说明、设置与无障碍、意见反馈，服务端授权 Admin 固定最后；名称与排版另做。
52. 手机结构：问卷中先选择 B（左边缘把手 + 底部 Menu），随后整组补充将其覆盖。手机取消左栏和左边缘把手，输入文章、单独查词、生词本、我的文章也全部集成到底部 Menu，避免左右两套入口造成混乱。

本轮追加纠偏：

- 首页桌面：胶囊悬停/聚焦后只浮出四个图标加短文字按钮，没有整高栏面；完全离开整体后短延迟收起。
- Reader 桌面：四个高频按钮固定显示；只保留现有位置的“回到首页”按钮，不显示 `Context Reader` 胶囊。回到首页直接落在彩球碰撞封面。

## 外刊图片入场清晰放大再次纠偏（2026-08-24）

用户在正常滚动速度下观察到的主要感受仍是“由模糊变清晰”，只有快速滚动时才能勉强看见放大；这不符合以外刊展示为招牌的目标。最新决定覆盖此前“缩放/清晰化”和“减少模糊”的表述：入场全程不允许模糊，图片应在接触视口底部时，以不受滚动速度影响的独立约 `0.5s` 时间线从清晰的较小状态明确放大到原尺寸。慢速、正常速度和快速滚动都应保留可辨认的放大，离开后复位，上下再次进入重播。

实现侧同时发现旧动画的外层从 `scale(.94)` 放大时，内图却从 `scale(1.09)` 缩到 `scale(1.035)`，两层视觉变化互相抵消，速度模糊又抢走了主要注意力。本轮因此冻结为外层 `scale(.90) → scale(1)`、内图基准缩放保持不变，并删除进入模糊和滚动速度模糊；最终相似度仍以用户设备上的正常速度滚动为视觉验收门槛。
