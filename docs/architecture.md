# Context Reader Architecture

## Overview

Context Reader is a Next.js app with a client-side reading workspace and server-side AI/helper routes. The shipped Home V2 supports two article entry modes:

- Plain text paste: stores and renders text only.
- URL import: server extracts public HTML into structured blocks, then the reader renders headings, paragraphs, lists, quotes, images, and inline upper/lower annotations.

Legacy image-import and OCR code remains available but has no `/home-v2` entry. Automatic OCR for images embedded in URL imports also remains disabled in the reader.

## Reading Flow

`app/home-v2/page.tsx` server-loads public recommendations and passes them to `HomeClient`, which owns the active article and home/reader state; `app/page.tsx` redirects `/` to `/home-v2`. Plain text articles pass only `article` into `ReaderView`. URL imports also pass `importedArticle`, which contains rich `blocks`. A text block's plain `text` remains the source for lookup, summaries, copying, and saved article identity; optional `inline` segments preserve visual annotations such as original `sup` and `sub` text. Image blocks render as article media with a click-to-enlarge zoom viewer. The viewer uses wheel zoom anchored at the cursor position, blocks background scrolling, exposes a download action, and renders clickable overlays when `layoutWords` are stored.

The shared/legacy image-import path can call `/api/ocr-image` and `/api/ocr-image-layout` in parallel, use layout text as a fallback, store the uploaded image as a data URL, and retain detected `layoutWords` or `layoutError`. It is not exposed by the shipped `/home-v2` homepage. `ReaderView` keeps `IMAGE_OCR_ENABLED = false`, so it does not automatically OCR arbitrary images embedded in URL imports; existing `ocrText` remains backward-compatible data. `ReaderView` tokenizes text blocks so word selection, phrase dragging, cached explanations, vocabulary saving, CSV export, and Anki import work across plain and URL-imported articles.

Saved articles live in browser `localStorage` through `lib/articles.ts`. `SavedArticle.importedArticle` is optional for backward compatibility. When present, reopening a saved URL import restores the original structured layout, images, supported inline annotations, and any OCR text already attached to image blocks instead of falling back to plain text.

`components/PronunciationButtons.tsx` always renders compact US/UK playback controls for explanations and vocabulary entries. Supported browsers use `SpeechSynthesis` with `en-US` and `en-GB` voices at a steady rate. Unsupported browsers keep both controls visible and report the capability limitation after interaction instead of removing the feature entry point.

## Article Editing

`ReaderView` edits article text in place rather than replacing the article with a textarea or a separate block editor. Read and edit states share `textBlockClassName`, so entering edit mode must preserve the same font size, line height, tracking, width, wrapping, and paragraph margins. Word lookup is disabled while editing. The toolbar provides global article undo and redo for the current reading session, not browser-native `execCommand` undo/redo. The history starts when the reader opens and remains available across edit mode and saved states until the user returns to the homepage. Imported article images are displayed but are not editable or uploadable; edit mode can remove an image block through the image's top-right delete button.

Plain text uses one `contentEditable` root containing the rendered paragraph elements. Imported articles also edit text blocks directly in the reading canvas while keeping image blocks read-only. Input events update the session history but still do not control the editable DOM on every keystroke, because rerendering controlled editable content moves the caret to the start. Save reads direct child text through `textContent`, normalizes non-breaking spaces, preserves explicit blank paragraphs as durable content, and serializes paragraphs deterministically. A no-op save exits without rewriting the article.

Imported articles edit each text block in place and rebuild `ImportedArticle` only when text actually changes. Empty accidental list-item blocks are removed on save, durable blank non-list paragraphs are preserved, image blocks are retained unless explicitly deleted, and an edited inline block drops its original `inline` segments when the new plain text no longer matches them. `lib/articles.ts::saveEditedArticle` preserves the saved article id, summary, creation time, and Anki-related local data while updating the body, title, rich blocks, and `updatedAt`.

Opening a saved article calls `touchSavedArticle`, refreshes `updatedAt` and the dedicated optional `lastOpenedAt`, and moves it to the front of the local array. `lib/savedArticleMerge.ts` collapses identical bodies and legacy `-local-recovered-*` lineages into one canonical original article, keeps the richest durable payload, carries forward the newest open/update time, and emits tombstones for every discarded id. The homepage saved-article menu therefore renders each logical article once and sorts by `lastOpenedAt`, falling back to legacy `updatedAt` and `createdAt` values. The reading-view vocabulary drawer can resolve a source sentence against all saved articles. Vocabulary created inside a public recommendation also stores an optional durable `sourceArticle` reference with the public id and title, so a source jump can load the recommendation directly without a local save; legacy entries without that field lazily scan the server-rendered public inventory, then persist the discovered reference through normal vocabulary sync. When the match is outside the current article, `HomeClient` starts a fresh reader session with that article before highlighting the source, preventing stale article state from consuming the jump request. Long articles use `content-visibility` with remembered intrinsic block sizes to keep normal scrolling responsive. Source jumps carry a monotonically increasing request id, retry until the target tokens exist, materialize the target block, and center it instantly without animating across the document. Imported image blocks persist source width and height when available so the browser reserves their aspect ratio before download. During a source jump, preceding legacy images without dimensions are promoted from lazy loading and their load/error layout events keep the target sentence centered for a short stabilization window. Location highlighting is presentation-only: the source sentence receives a quiet highlight and the selected vocabulary word or phrase receives a stronger amber underline treatment without focus changes, article edits, history entries, or cache-key changes.

## Translation Flow

Sentence context uses punctuation-aware boundary scanning so periods inside common abbreviations, names and initials, numbers, numbered labels, domains, email addresses, and similar dot-joined tokens do not split lookup context prematurely.

Word and phrase lookups send only the selected text plus current, previous, and next sentence context to `/api/explain-word` and, on cache misses, `/api/explain-word-stream` in parallel. The stream uses fixed labels for lemma, phonetic, part of speech, difficulty, meanings, sentence translation, usage, collocations, and examples. `ExplanationPanel` parses those labels into one progressive visual tree. When both requests complete, `lib/explanationDisplay.ts` merges the stream's visible fields into the structured response, caches that merged explanation by `word + sentence`, and keeps the completed stream text rendered. The structured response contributes hidden fields such as Anki metadata; it does not replace the visible stream. Cache replay formats the merged fields back into the same fixed-label text, preserving content, order, spacing, and wrapping. `scrollbar-gutter: stable` prevents action controls from triggering width reflow. Collocations include parenthesized Chinese translations. Repeated taps do not restart an in-flight lookup; the circular regenerate control forces a new result and, when the same `word + sourceSentence` exists in vocabulary, replaces its generated fields while preserving id, creation time, and Anki import status.

Full-article translation uses `/api/translate-article` and appears in the reading view's right sidebar. Users start a new translation from inside that sidebar; there is no top-bar full-translation button and merely entering the sidebar does not start new AI work. The client derives translation blocks through `lib/articleTranslationBlocks.ts`, requests one text block at a time, appends each completed translation to the sidebar, and immediately persists both the current merged partial result and the completed per-block entry in `localStorage`. Those cache objects enter account sync independently of saved-article objects, so signed-in users can reopen the same recommendation on another device without first saving the article. Partial results therefore survive route changes, refreshes, browser restarts, and account sync; returning to an already-started incomplete article resumes only missing blocks. Public/admin preloads seed only missing whole-article cache keys, and preloaded explanations likewise seed only missing explanation keys, preserving the member's cloud-restored or regenerated values. After article editing, unchanged block keys reuse their cached translations while changed blocks are marked stale; “更新已修改部分” requests only those changed blocks. Keep the batch size at one block unless there is a deliberate UX tradeoff, because the first translated paragraph should appear as soon as it is ready and later paragraphs should continue appearing after it. Each translation request includes the full current article as `contextBlocks`, so one-block requests still give the model article-level context. Switching back to word explanations must not abort the in-flight translation. Provider rate limits, overloads, timeouts, network interruptions, and the local concurrency cap use bounded queueing plus cancellable exponential backoff; quota, provider balance, and configuration failures remain explicit non-retryable errors. The circular regenerate button clears the matching whole-article and per-block caches before forcing a complete new translation of all current text blocks with full context. `lib/articleTranslationJobs.ts` estimates remaining time from elapsed time and completed blocks.

## Homepage

`ArticleInput` and `ImmersiveHome` retain legacy/shared entry behavior, but they are not the visual source of truth for the shipped homepage. `/home-v2` owns the current book-space UI; reusable article import, saved-article, vocabulary, account, and `ReaderView` contracts remain shared beneath it.

`app/home-v2/page.tsx` is the shipped continuous book-space homepage in the same Next.js deployment; `app/page.tsx` redirects `/` to `/home-v2`. It server-loads the public-article payload and renders `HomeClient` with `homeVariant="book"`; `HomeClient` retains the active article, cache preload, saved-article, vocabulary-source, and `ReaderView` boundaries. `BookHome` owns one fixed book scene with `foreword`, `workbench`, and `recommendations` chapters plus a closed cover. The full scroll track exists on first paint. One normalized page-scroll value directly seeks the cover pose and both inner turns, so changing wheel direction at any intermediate frame retraces the same cover angle, paper curvature, clipping, and contact shadow without waiting for a timer. The hard front board keeps a constant half-spread width while its hinge moves from the centered closed-book position to the central spine; the back board and page block translate separately into the right half. Directory jumps create one source-to-target sheet even when they skip a chapter. The foreword leaves the left page empty; its right page stays completely blank through the cover endpoint and an additional 280ms visual pause, then reveals title glyphs from clipped lines, uncovers semantic copy blocks in sequence, and lands the signature last. That staged reveal belongs only to the closed-cover entry. As soon as the foreword participates in an inner-page turn, `BookHome` promotes it to a persistent printed state, and `CurvedPageTurn` forces every cloned foreword reveal part to its final visible styles before the page-flip engine receives the snapshot. Returning from the workbench or recommendations therefore bends a page that already contains the complete foreword and does not replay the reveal after landing. Leaving the first cover-entry foreword before the pause completes cancels the pending reveal; fully closing the cover rearms it. The workbench uses a real tokenized micro article with the shared explanation panel; standalone lookup is the default right-page tab, while paste and URL remain available in place and the latest saved article remains conditional. All three mode panels stay mounted and only the selected panel is exposed, so changing modes does not destroy an in-progress or completed dictionary lookup. `BookDictionary` renders in compact mode inside the scrollable right page, so lookup does not replace the whole spread. The removed preference chapter is now a modal state over recommendations. `CurvedPageTurn` is the selected desktop B hybrid engine: it keeps every real React spread mounted and interactive, clones the current and target spreads into an `aria-hidden` visual sheet, copies live form values and every nested scroll surface's current offsets, and seek-controls the dynamically imported MIT `page-flip` engine over the persistent custom cover/spine/page-block shell. The folded sheet therefore depicts the exact visible page state instead of resetting an internally scrolled dictionary or recommendation page to its top. `BookLetterField` computes pointer-mask rectangles only from currently displayed and visible reading regions, so hidden workbench content cannot erase letters over the blank foreword page. At `760px` and below, the homepage instead uses ordinary single-column vertical scrolling and discrete chapter boundaries: it does not mount `CurvedPageTurn` or the WebGL ambient field, does not seek scroll-linked 3D poses or shadows, and uses a static colored cover treatment plus the small touch ripple. Reduced-motion desktop uses a short page-edge fallback. Reader entry is delayed only long enough for the desktop page or recommendation-cover expansion, then mounts the existing `ReaderView`; returning restores `/home-v2`. Homepage image upload remains intentionally absent. See `docs/home-v2-implementation-contract.md` for the authoritative interaction contract.

`BookHome` also owns a small idle-settle controller around that same normalized scroll value. It records the last real scroll direction, waits about 90 ms only while progress is inside a cover or inner-page turn interval, and advances the browser scroll to that sheet's adjacent boundary in at most about 480 ms. The longer, material-aware settle keeps the soft-sheet curve, reverse face, occlusion, and moving contact shadow visible instead of compressing the characteristic middle fold into a rigid jump. Wheel, touch, and scroll-key intent cancel the request-animation-frame settle before native scrolling resumes, so reversing still starts from the current pose. Click-driven cover and directory navigation uses the same cancellable frame controller with a capped duration instead of browser-native smooth scrolling; the page-flip renderer never becomes a second animation authority.

On desktop, the workbench right page and recommendation page own wheel input while they have remaining internal scroll range. When a gesture reaches the workbench bottom or recommendation top, `BookHome` records that boundary and consumes continued same-direction wheel events until there has been about 520 ms without another event. The next gesture after that quiet interval is allowed to bubble to the story scroll and turn the page. This separates deliberate page turning from trackpad momentum without adding another animation authority; non-scrollable pages and mobile keep their existing behavior.

The paper material depends on several implementation invariants, not only on visual CSS. Snapshot pages stay `soft`, use a sine-shaped vertical lift through the middle of the turn, preserve visible overflow around the page-flip renderer, and keep the renderer measurable even while its parent is visually hidden. Hiding `.engine` with `display: none` lets a same-frame `seek` measure `0×0` and offsets the sheet to the viewport's upper-left; clipping the renderer removes the visible curve. Endpoint handling is transactional: a small seek epsilon keeps the temporary sheet alive until the boundary, `BookHome` uses a larger scroll-rounding epsilon to choose the settled chapter, and `finishTurnVisual` commits the real target spread before clearing the snapshot on the next animation frame. A new turn cancels any pending clear. This prevents both the upper-left sheet jump and the post-turn flash back to the outgoing chapter. The exact protected values and regression matrix live in `docs/home-v2-implementation-contract.md`.

`BookDictionary` consumes `/api/dictionary-stream` as newline-delimited structured events. Each complete event mounts the matching final UI block in order, and the accumulated event model becomes the saved and cached `DictionaryResult` without swapping to a separately generated layout when streaming finishes. Pronunciation controls appear with the head block. The route uses the existing DeepSeek model defaults, disabled thinking mode, concurrency guard, execution ledger, and estimated-cost recording. The browser keeps a bounded per-tab result cache and latest result in `sessionStorage`; the same component and session are reused in the Home V2 workbench and the reader's third right-sidebar tab. Saving a standalone result creates a source-sentence-free vocabulary entry: collapsed cards show the combined Chinese senses; expanded cards parse both new and legacy saved strings into separate usage points, collocations, synonyms, word family, examples, mistakes, and memory guidance. Its Anki mode is `basic_en_to_cn`: English remains alone on the front, while the back uses the same structured study hierarchy plus IPA and native US/UK TTS controls. Article-derived cloze and CN-to-EN cards are unchanged. `BookRecommendations` receives the server-rendered `initialPublicArticles`, rejects recommendations without the required cover, and keeps a physical center spine in the embedded spread. Without personalization it uses a daily-stable order drawn first from CET-4/CET-6/postgraduate/IELTS/TOEFL inventory; the recommendation dialog applies level, pace, and interest scoring immediately. Future reading-history inference should seed that profile but must allow manual correction. Recommendation hover/focus prefetches article details, and the clicked cover expands before the existing public-article-to-ReaderView flow. When the published inventory is empty it shows an explicit inventory state rather than fabricated articles. `/api/feedback` validates same-origin bounded JSON or multipart input and stores private feedback JSON plus optional validated image attachments in the `context-reader-feedback` Supabase Storage bucket. Desktop home-only cursor letters reuse the original colored density and render above the closed cover, opened pages, controls, forms, Menu, and overlays; the canvas mask removes them only around the marked article and explanation reading regions, and `ReaderView` unmounts the field. Mobile has no persistent ambient letters and emits only a small touch ripple.

Public recommended articles are fetched in the server `app/home-v2/page.tsx` and passed into the client homepage as `initialPublicArticles`. Do not move this list back to a client-only `useEffect` fetch; otherwise the recommendation spread first renders without them and visibly fills them in later. Saved articles belong to the shared Menu rather than the recommendation spread.

The reading view uses the same vocabulary data but keeps the notebook as a right-side drawer so it does not cover the article workspace. Both notebook placements lock the underlying page at its current scroll position while preserving an explicitly sized, `min-height: 0` internal scroller for the notebook. The homepage's global wheel/touch teaching locks and desktop scene snapping must ignore events from marked local-scroll surfaces, and notebook overscroll stays contained instead of reaching the page. Vocabulary is always sorted by `createdAt` descending after normalization, deduplication, and cloud merge, so account login cannot inherit the sync table's object-key order. Entries use TanStack Virtual with stable entry keys, transform positioning, small bounded overscan, content-aware unmeasured-height estimates, animation-frame ResizeObserver batching, and live element measurement. Scrollbar dragging does not trigger compensating scroll-offset writes as new rows are measured. Only rows near the viewport mount, hidden homepage animation frames and CSS animations pause while the notebook is open, and the overlay avoids a full-screen backdrop filter. Do not reintroduce fixed oversized rows or React state updates on every scroll event; short cards should stay compact and long cards should remain fully visible.

Shared tool panels should not preserve stale interaction traces across open/close cycles. `VocabularyPanel` clears its search, preview, and expanded-detail state and scrolls its list to the top when opened or when the filtered list changes. Vocabulary rows always show IPA when available plus the original core fields; usage notes, collocations, and bilingual examples are progressively disclosed by the per-entry `显示全文` control. Rows continue to use measured content heights before and after expansion. `lib/vocabularySearch.ts` builds a sorted normalized-word index once per ordered collection and resolves prefix searches with binary bounds, so query cost scales with matches rather than total stored vocabulary. Browser TTS voice discovery and warmup are shared across memoized pronunciation controls rather than repeated when virtual rows mount. The Home Menu vocabulary preview uses fixed compact virtual rows without per-row resize observers, disables their pointer targets while the list is actively scrolling, and therefore does not replace the hover detail for every row passing beneath a stationary pointer. Parent views clear temporary vocabulary errors and Anki status when the drawer/dialog closes.

## Mobile Reader

The mobile reader keeps the article as the primary single-column surface and puts a fixed tap-only tool dock above the safe area. Explanation, full-article translation, standalone lookup, vocabulary, and lower-frequency article actions share a resizable bottom sheet; switching tools changes the sheet body without moving the reading position. Explanation opens around half the viewport height, while the other tools may use a taller default. Opening full-article translation must not start the job automatically. Anki import controls are absent on mobile but remain available on desktop. The sheet owns its local scroll and overscroll containment, and only its compact handle/collapse control stays fixed while content scrolls.

Touch word selection separates reading scroll from lookup gestures. Vertical movement is treated as article scrolling and should not highlight or query a word. A tap explains one word. Horizontal movement across words or long-press selection can select a short phrase, capped at eight words.

Each new explanation resets the bottom sheet to its default half-height and scrolls the explanation content to the top. Collapsing the explanation panel should preserve the article reading position, but temporary panel state should not leak into the next lookup.

## Account, usage, and sync

Account sync transport uses byte-bounded response pages, and continues paging past Supabase's default 1,000-row limit up to the route's 20,000-object cap. Automatic learning-data sync remains active on `/admin` only for the developer account so vocabulary and locally saved articles created inside the real ReaderView are durable; password-only Admin sessions have no account sync. Normal pages serialize writes both within one tab and across tabs with the Web Locks API.

`AccountProvider` loads `/api/auth/session`, opens the phone/password form only for restricted actions, schedules cloud sync after durable local changes, and requires a successful final sync before explicit logout clears browser data. Phone registration collects a nickname, maps the unverified mainland-China phone identifier to a reserved server-only Auth email, and stores the six-digit numeric password through Supabase's password hashing. Legacy email-link adoption remains compatible but is hidden from the current UI. `lib/accountSyncClient.ts` stores each article, vocabulary entry and explanation/translation cache item as an independent versioned object; cache durability does not depend on saving the article. Server reads page through all account objects instead of relying on Supabase's default 1,000-row response cap. Supabase compare-and-swap prevents stale devices from overwriting newer versions; client writes are single-flight, unique by kind plus object key, and retry against a fresh complete version list. The client compares normalized JSON payloads with stable key ordering and skips unchanged objects. Article conflicts resolve to one canonical article and discarded duplicate ids become tombstones; article sync must never create a visible recovery copy. The sync API also converts any legacy `-local-recovered-*` article write into a tombstone so an older open tab cannot resurrect deleted copies. After a cloud merge, `HomeClient` refreshes its saved-article state from durable storage immediately instead of showing a stale pre-sync count until reload. Vocabulary versions are normalized, merged and deduplicated by word plus source sentence while preserving optional public-article source metadata; redundant recovery ids become tombstones, while a genuinely ambiguous same-id/different-identity local value is preserved in a separate local recovery store and never counted as a notebook entry. Article and vocabulary deletions are persisted as tombstones so another device cannot silently restore them.

Saving an article commits the local article object and schedules account sync before requesting its generated Chinese list summary. Summary or provider failures therefore leave the article saved and retryable instead of rolling back the durable article record.

All cost-bearing routes use `lib/usageGate.ts`. Structured and streaming word lookup requests share `x-context-action-id`, so the quota action is idempotent while `usage_executions` stores both real upstream calls. Registered-user failures are refunded and cache hits are free; guest cached lookups call `/api/usage/cache-lookup`. Full translation, summaries, sentence questions and OCR require login. `/account/usage` is the user view; the unified `/admin` console manages public recommendations, users, ordinary-user limits, provider cost summaries, and feedback. Admin quota rows are grouped by Chinese product meaning, batch-save the fixed metric/window pairs for each ordinary plan, and intentionally hide the developer allowance plus unconnected price settings.

The browser never receives a Supabase key. Without account infrastructure, reading and a browser-enforced ten-lookup fallback remain available, while login and authenticated high-cost features remain disabled.

## API Routes

`middleware.ts` and `lib/requestSecurity.ts` form the common request gate. They apply trusted Vercel IP extraction, route-specific fixed-window limits, daily costly-operation limits, `413` early rejection, same-origin admin checks, request ids, and private admin cache headers. `lib/limitedBody.ts` also counts actual streamed bytes before JSON or multipart parsing, so missing or forged `Content-Length` cannot bypass route limits. `lib/costConcurrency.ts` caps simultaneous AI and OCR work per server instance and releases leases on completion, error, stream cancellation, or client disconnect where the upstream route exposes a signal.

All user-controlled outbound URL reads use `lib/safeRemoteFetch.ts`. It accepts only standard-port HTTP(S), rejects credentials and non-public/reserved IP ranges, resolves and pins the verified IP for the actual TCP/TLS connection, preserves the original Host/SNI, rechecks every redirect, and streams responses through hard byte caps. AnkiConnect accepts only local `127.0.0.1:8765` and has an eight-second timeout.

- `/api/public-articles`: lists public recommended articles for clients and service-worker caching. The homepage does not depend on a client-side call for first paint.
- `/api/public-articles/[id]`: reads one public article plus its preloaded word explanations and full-article translation caches.
- `/api/auth/*`: registers/signs in phone + numeric-password accounts, retains legacy email OTP and hosted-session adoption, reads/refreshes the current account session, and logs out through server-managed cookies.
- `/api/account/sync`: reads and compare-and-swap merges versioned account objects; `/api/account/export` returns the member's profile, synced objects, and usage-action history.
- `/api/usage/cache-lookup`: records cached guest lookups as trial usage without charging authenticated cache hits.
- `/api/admin/*`: handles public article listing/publishing/deletion, account/quota administration, private feedback listing/status/deletion, and detailed error-report review. `lib/adminAuth.ts` accepts a server-verified user whose entitlement is `admin` or the signed legacy password-admin cookie; client-side menu visibility is never the authorization boundary. Writes still require same-origin requests.
- `/api/import-url`: fetches public HTML, removes nested non-article subtrees by semantic tag/role/id/class, scores balanced article containers instead of truncating nested `<div>` elements with a regex, and applies a second block-level trailing-section boundary. Navigation, source/citation panels, related/recommended stories, newsletters, comments, social tools, and other page chrome are excluded before `ImportedArticle` is returned. The importer still normalizes image URLs, preserves `sup`/`sub` inline segments, removes embedded personalization/follow/alert modules, and keeps standalone advertisement labels only when the surrounding article is substantively about advertising.
- `/api/ocr-image`: extracts text from one uploaded image up to 8MB.
- `/api/ocr-image-layout`: detects word boxes for multipart uploads, data URLs, or remote image URLs and returns percentage coordinates plus line context.
- `/api/ocr-image-url`: extracts text from a remote image URL. The route is enabled, but the URL-import reader does not call it automatically while its OCR gate is off.
- `/api/download-image`: fetches and validates a remote image up to 20MB and returns it as a short-lived private attachment.
- `/api/explain-word`: sends only selected word/phrase and sentence context to DeepSeek.
- `/api/explain-word-stream`: sends the same selected context to DeepSeek and streams fixed-label Chinese text whose completed visible fields are merged into the durable explanation.
- `/api/dictionary`: accepts one English word or a phrase of up to eight words, consumes one `lookup_generation` unit, and returns a detailed context-free dictionary result. It uses the same DeepSeek defaults, request-size limits, execution ledger, estimated-cost recording, and AI concurrency guard as the other generated lookup paths.
- `/api/translate-article`: translates sanitized article text blocks to Chinese for the full-article translation sidebar. The client requests one text block at a time with `contextBlocks` containing the full article, while the route briefly queues behind the in-process cost cap, passes a privacy-safe hashed `user_id` for provider scheduling isolation, and returns structured retry codes that distinguish temporary provider pressure from quota, balance, and configuration failures.
- `/api/summarize-article`: summarizes saved articles for the homepage list.
- `/api/ask-sentence`: answers follow-up questions about a selected sentence.
- `/api/anki/*`: checks/creates Anki helpers, while browser-side AnkiConnect is still required for local note import.

DeepSeek-backed routes default to `deepseek-v4-pro` and send `thinking: { type: "disabled" }` in completion requests. `DEEPSEEK_MODEL` is the shared override, while `DEEPSEEK_TRANSLATION_MODEL` takes precedence for full-article translation. Structured word explanations can retry comma-separated `DEEPSEEK_FALLBACK_MODELS` on the primary provider and can use a secondary `DEEPSEEK_FALLBACK_BASE_URL` with optional fallback key/model; sentence questions also use the fallback model list. The word explanation route sends compact `w/s/p/n` JSON keys to reduce request tokens; the full-article translation route accepts target article blocks plus optional full-article context blocks and sends compact `[id,type,text]` tuples to DeepSeek while preserving id-aligned JSON output.

## Anki Templates

`lib/ankiTemplates.ts` defines the Context Reader cloze and basic note types. The import flow calls `ensureModel`, so existing note templates are updated before new notes are added. Cloze-card front prompts are generated locally in `lib/ankiData.ts` from the durable explanation's exact `contextMeaning`: only that word-or-phrase translation appears after the large gap, with no basic meaning, sentence translation, fallback, or added label. Card backs include Anki native TTS replay controls for US and UK pronunciation. The UK control requests `en_GB` without hard-coding voice names, allowing Anki to select an installed British English voice across operating systems. Standalone `basic_en_to_cn` notes keep an English-only front and render a complete back with headword metadata, IPA, both TTS controls, Chinese senses, formatted usage points, collocations, synonyms, word family, examples, mistakes, and memory guidance.

The app does not generate or store `[sound:...]` media files for pronunciation. During import, `addVocabularyNote` tries to set the target deck config's `autoplay` option to `false` through AnkiConnect so the card back does not auto-play pronunciation and users click the replay controls instead. If an older AnkiConnect/Anki combination cannot save deck config, note import still proceeds and the user can turn off audio autoplay in Anki deck options.

## Public Recommendations

Public articles are stored in Supabase tables created by `docs/public-articles-supabase.sql`. The Admin intake surface treats browser-local saved articles, pasted text, and URL import as equal entry modes in one candidate editor. URL intake reuses `/api/import-url`, preserves meaningful inline images, and receives description plus cover candidates. `/api/admin/article-classification` uses DeepSeek when configured and local readability/topic rules as a fallback. It produces a Chinese summary, Chinese learner difficulty, CEFR reference, audience stages, interest topics, reading time, timeliness, and review notes. Those classification fields are displayed as system-owned output rather than editable admin choices.

Candidates reuse `public_articles` rows with `published=false`. Recommendation metadata is stored in `imported_article.recommendation`, including the required cover URL and attribution, so existing production tables do not need a destructive schema migration. `lib/articleContentSanitizer.ts` also trims recognized trailing website sections when old remote-URL candidates are mapped for Admin preview and immediately before publication; publishing persists the cleaned body and blocks, while plain pasted candidates are untouched. Missing-cover candidates remain editable but cannot publish. `/api/admin/article-covers` uploads reviewed files to the public `public-article-covers` Supabase Storage bucket. Candidate and published rows mount the same `ReaderView` used by normal reading. Its optional `onArticleEditCommit` waits for the Admin candidate/public API to persist body and structured-block edits before closing edit mode; failures remain visible in the existing Reader status area. Title, summary, classification, and cover stay in the metadata editor. When a candidate matches an existing public source URL or pasted-article identity, publishing updates the public row and removes the draft instead of creating a duplicate. Existing explanation and full-translation caches still use `article_id + cache_key` rows in `public_explanations` and `public_article_translations`.

`lib/recommendationSources.ts` is the crawler source whitelist. `lib/recommendationCrawler.ts` reads RSS/Atom feeds through the pinned-DNS remote fetch helper, accepts only article hosts declared by each source, removes tracking parameters, deduplicates against both candidate and public rows, and reuses `/api/import-url` for the same balanced-container and trailing-noise cleanup as manual URL intake before classification. A run stops after two successful additions or its bounded execution budget. Difficulty filtering happens after classification. Missing-cover results remain candidates and cannot publish. Feed failures and blocked article pages are isolated as per-item or per-source skips so one source cannot abort the whole run.

`POST /api/admin/article-crawler` performs an authenticated manual run with topic, optional difficulty, and target inventory. `GET /api/admin/article-crawler` returns source and schedule status. `GET /api/cron/recommendations` is called once daily by Vercel Cron, rotates across the six topics, and targets six candidate-or-public articles per topic. It requires `Authorization: Bearer $CRON_SECRET` and fails closed when the secret is absent. Cron delivery can be duplicated, so source-URL deduplication is part of the job's idempotency boundary; crawler output always enters review rather than publication.

The three public-content tables enable RLS and revoke all direct table privileges from `anon`, `authenticated`, and `PUBLIC`. Only the server-side service-role path reads or writes them; applying the SQL to the real Supabase project is part of deployment, not merely a documentation step.

When the public-recommendation scene becomes visible, `HomeClient` prefetches the visible article details and deduplicates hover, focus, and click requests in memory. The public-article server read fetches explanation and translation-cache rows in parallel after locating the article. On open, `HomeClient` writes returned `articleTranslations` only when the corresponding browser cache key is absent, so an account-synced member translation remains authoritative. The reader then opens the full-article translation sidebar from cache instead of regenerating when the cached block hash matches the article text.

The admin UI follows one sequence: choose a browser-local, pasted, or URL source; accept automatic classification; review the cover and summary; save a candidate; open it in the real reading layout; then publish selected candidates. Both candidate and published lists can enter that ReaderView and persist in-place body edits to their own row. Topic-based discovery is a secondary collapsed intake source that reports inventory movement and skipped-item reasons but never publishes. The public list owns delete and per-row cache-refresh maintenance, so there is no duplicate local-article publishing selector. Visitors can read public articles without logging in.

Feedback submitted by `FeedbackPanel` or the Home Menu is stored as bounded private JSON under month folders in the `context-reader-feedback` Supabase Storage bucket. Multipart submissions may add at most three JPEG/PNG/WebP/GIF files of at most 5 MB each under validated private attachment paths. `/api/admin/feedback` lists at most the latest 300 JSON objects in bounded batches, serves validated attachments only after admin authorization, treats older objects without status as new, updates `new`/`resolved` status by replacing the same private object, and deletes the JSON object together with its validated attachments. The Admin view shows image previews but deliberately omits user-agent and Storage paths from its visible content.

`lib/clientErrorReporting.ts` is the user-facing error boundary for browser requests. It preserves explicit 4xx input/auth/quota explanations, distinguishes a confirmed offline browser from an otherwise unreachable site, and converts 5xx failures into a maintenance message with a traceable id. Unsupported standalone dictionary input is rejected before network work: Chinese input explains that Chinese-to-English is not available yet, and whole sentences direct the learner back to article-context lookup. Network and user-input failures are not stored as product bugs.

`lib/serverErrorReporting.ts` and `lib/errorReportStore.ts` persist site, provider, configuration, and client-processing faults as deduplicated private JSON under `errors/YYYY-MM/` in the feedback bucket. Each record includes operation, endpoint, user-facing and technical messages, stack, status/code, safe metadata, browser/user identity when available, deployment version, occurrence count, resolution state, and email-delivery state. The record is written before SMTP/Resend delivery; repeated email for the same fingerprint is suppressed for fifteen minutes. `/api/error-reports` is bounded, same-origin, and rate-limited for client-only failures. Only `/api/admin/error-reports` can list, update, or delete records.

## Offline Behavior

The production app registers `public/sw.js` as a service worker. After the site has been opened online once, the cached app shell can reopen offline. Public article API responses use network-first caching, expire after seven days, and are capped at fifty entries, so public articles that have already been loaded can reopen offline without growing an unbounded or indefinitely stale cache.

`AccountProvider` separates server authentication from offline local access. Every successful authenticated session writes a minimal `context-reader:last-account-session:v1` snapshot containing only the user id, nickname, and verification time. A failed `/api/auth/session` request, an explicit browser `offline` event, or a server-side account-service `503` changes the client to offline mode, removes all server-authorized account state, and reopens local data only when that snapshot exists. The UI keeps an always-visible offline banner and the Menu labels the identity as offline. The snapshot must never restore plan, usage, Admin visibility, or authorization for any API route.

An offline remembered account can open, save, and edit browser-local articles, read and modify its local vocabulary, and replay cached explanations, standalone dictionary results, and full translations. Those local mutations continue to emit the existing account-data events and sync after the server session is verified again. New AI explanations, standalone dictionary generation, full-article translation, URL import, image OCR, feedback submission, article summaries, cloud sync, and usage reads require network access and must show an offline-specific message instead of opening a login prompt.

## OCR Provider Framework

`lib/visionOcr.ts` provides both plain-text extraction and layout-word detection. It supports `OCR_PROVIDER=zhipu` with `ZHIPU_API_KEY`, `ZHIPU_BASE_URL`, and `ZHIPU_OCR_MODEL`, and `OCR_PROVIDER=openai` with `OPENAI_API_KEY` and `OPENAI_OCR_MODEL`. If `OCR_PROVIDER` is omitted, the provider layer prefers Zhipu when `ZHIPU_API_KEY` exists, otherwise OpenAI when `OPENAI_API_KEY` exists.

The homepage and OCR routes are enabled. Enabling automatic OCR for URL-imported article images is a separate product decision controlled by `IMAGE_OCR_ENABLED` in `components/ReaderView.tsx`; it must account for request volume, provider reliability, persisted block metadata, and public/admin replay before that gate changes.

## Design

The reading workspace keeps the quiet utility treatment: no global black nav, compact rounded white surfaces, a system font stack, and Action Blue `#0066cc` for core reader controls. The homepage uses a light continuous depth scene, editorial serif sentences, blue reading actions, restrained coral/blue connective lines, and purposeful loading and scroll transitions. These effects teach actual reading gestures; they must not appear inside the article reader or obscure the first-screen entry.
