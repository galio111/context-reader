# Context Reader Architecture

## Overview

Context Reader is a Next.js app with a client-side reading workspace and server-side AI/helper routes. The shipped Home V2 supports two article entry modes:

- Plain text paste: stores and renders text only.
- URL import: server extracts public HTML into structured blocks, then the reader renders headings, paragraphs, nested ordered/unordered lists, quotes, captions, tables, images, and inline upper/lower annotations.

Legacy image-import and OCR code remains available but has no root-homepage entry. Automatic OCR for images embedded in URL imports also remains disabled in the reader.

Primary production runs at `https://context-reader.com` on a Tencent Lighthouse instance. Caddy terminates HTTPS and proxies the unchanged Next.js application to a private Docker network containing PostgreSQL 17, GoTrue Auth, PostgREST, Storage API, and the internal Supabase-compatible gateway. The browser still receives no database or service-role key. The former Vercel deployment and managed Supabase project are frozen rollback evidence only; production never reads or writes them.

## Reading Flow

After extraction, `removeDuplicateImageCaptionBlocks` compares an image's normalized alt/caption with the immediately following text block and removes only an exact duplicate. Distinct prose remains intact, while the surviving figure caption continues through the normal Reader token path and supports contextual lookup.

`app/page.tsx` server-loads public recommendations and passes them to `HomeClient`, which owns the active article and home/reader state. `app/home-v2/page.tsx` permanently redirects legacy links to `/` while preserving their query string. Plain text articles pass only `article` into `ReaderView`. URL imports also pass `importedArticle`, which contains rich `blocks`; a successful URL submission goes directly to Reader without an intermediate preview. A text block's plain `text` remains the source for lookup, summaries, copying, and saved article identity; optional `inline` segments preserve visual annotations such as original `sup` and `sub` text. Table blocks keep caption, row/cell text, header scope and bounded row/column spans. They remain inside the article measure on desktop, use a local horizontal scroller on narrow screens, and tokenize each cell so contextual lookup remains available without turning the entire page into a horizontal scroller. Ordered list start values and bounded nesting levels also survive import. Fresh external images receive a short 1.8-second localization budget: normal sources finish before Reader opens and therefore display as first-party images with the text; only slower sources enter Reader with reserved aspect ratios and an explicit background-saving notice that source instability may remove individual images without affecting the article. A background first-party replacement never returns to the full-page skeleton or changes the text. Cross-article vocabulary jumps still wait for any applicable local-media gate before locating the target token. Image blocks render as article media with a click-to-enlarge zoom viewer. Each wheel step anchors the source pixel beneath the pointer's current position, even after the pointer moves between steps; animation-frame interpolation changes only the viewer transform and never rerenders the article. The viewer blocks background scrolling, exposes a download action, and renders clickable overlays when `layoutWords` are stored.

The shared/legacy image-import path can call `/api/ocr-image` and `/api/ocr-image-layout` in parallel, use layout text as a fallback, store the uploaded image as a data URL, and retain detected `layoutWords` or `layoutError`. It is not exposed by the shipped root homepage. `ReaderView` keeps `IMAGE_OCR_ENABLED = false`, so it does not automatically OCR arbitrary images embedded in URL imports; existing `ocrText` remains backward-compatible data. `ReaderView` tokenizes text blocks so word selection, phrase dragging, cached explanations, vocabulary saving, CSV export, and Anki import work across plain and URL-imported articles.

Saved articles live in browser `localStorage` through `lib/articles.ts`. `SavedArticle.importedArticle` is optional for backward compatibility. When present, reopening a saved URL import restores the original structured layout, images, supported inline annotations, and any OCR text already attached to image blocks instead of falling back to plain text. A fresh URL import may hold selected external image sources only in the active Reader while its anonymous, bounded background localization runs. Successful images swap to first-party Storage URLs in place; failed fresh-import images are removed without changing the text or failing the article. If the user saves before localization completes, the resulting first-party/removed-image state is patched into that saved copy. A historical browser-only article that still contains an external image enters Reader immediately and starts the authenticated `/api/article-images/localize` repair in the background; that repair preserves failed sources for later retry. Every successful saved-article replacement is persisted locally and normal protocol-2 sync carries the updated payload to the account without clearing unrelated data. The shared article sanitizer rejects author identity media using high-confidence source semantics such as account/headshot namespaces, or a small person-labelled thumbnail immediately paired with the same name and a byline role; it removes that adjacent author label as one card. This rule applies to new URL imports and mapped historical remote candidates, while ordinary large editorial portraits remain article content. The pinned-DNS IPv4 guard blocks exact private, link-local, carrier, documentation and reserved ranges rather than broad public `/16` ranges; for example, the public WordPress VIP address `192.0.66.108` used by `science.nasa.gov` must remain reachable while `192.0.0.0/24` and `192.0.2.0/24` remain blocked.

`components/PronunciationButtons.tsx` always renders compact US/UK playback controls for explanations and vocabulary entries. `/api/pronunciation` reads or generates a provider MP3 and returns identical audio across browsers and devices. Successful client requests are reused in memory and generated files are content-addressed in the private `context-reader-pronunciation` Supabase Storage bucket. Active explanation, dictionary-result, Anki-preview, and Menu-detail surfaces request both accents in the background before the user clicks; playback resumes the browser audio context during the click and decodes the returned MP3 without relying on browser text-to-speech. A still-pending first generation is visibly labeled `准备中`. Cloud failure remains explicit and never silently switches to `SpeechSynthesis`, because that would make Chrome, Edge, and mobile devices sound different.

## Article Editing

`ReaderView` edits article text in place rather than replacing the article with a textarea or a separate block editor. Read and edit states share `textBlockClassName`, so entering edit mode must preserve the same font size, line height, tracking, width, wrapping, and paragraph margins. Word lookup is disabled while editing. The toolbar provides global article undo and redo for the current reading session, not browser-native `execCommand` undo/redo. The history starts when the reader opens, is bounded to the latest 100 snapshots, and remains available across edit mode and saved states until the user returns to the homepage. Undo and redo are synchronous draft-only operations: they never write saved-article storage, invoke Admin persistence, or mark an article saved. Only the explicit Save action performs the external commit. Imported article images are displayed but are not editable or uploadable; edit mode can remove an image block through the image's top-right delete button.

Plain text uses one `contentEditable` root containing the rendered paragraph elements. Imported articles also edit text blocks directly in the reading canvas while keeping image blocks read-only. Input events update history refs and an isolated undo/redo availability store; they do not rerender `ReaderView` or control the editable DOM on every keystroke, because reconciling browser-owned editable content can overwrite the latest input and move the caret. Applying an undo or redo snapshot deliberately remounts the draft surface so the visible DOM cannot diverge from the history index. Save reads direct child text through `textContent`, normalizes non-breaking spaces, preserves explicit blank paragraphs as durable content, and serializes paragraphs deterministically. A no-op save exits without rewriting the article. Edit entry, block deletion, undo, redo and save all capture a block-relative viewport anchor before changing the draft tree and restore it during the corresponding layout commit; if the anchored image or table was deleted, restoration falls through to the next surviving block at that index and then to the stored scroll ratio.

Imported articles edit each text block in place and rebuild `ImportedArticle` only when text actually changes. Empty accidental list-item blocks are removed on save, durable blank non-list paragraphs are preserved, image and table blocks are read-only and retained unless explicitly deleted, and an edited inline block drops its original `inline` segments when the new plain text no longer matches them. `lib/articles.ts::saveEditedArticle` preserves the saved article id, summary, creation time, and Anki-related local data while updating the body, title, rich blocks, and `updatedAt`.

Opening a saved article calls `touchSavedArticle` before entering Reader, refreshes `updatedAt` and the dedicated optional `lastOpenedAt`, moves it to the front of local state immediately, and then schedules normal account sync. The homepage saved-article menu and Continue Reading therefore change on the same click instead of waiting for a later cloud-sync pass. `lib/savedArticleMerge.ts` collapses identical bodies and legacy `-local-recovered-*` lineages into one canonical original article, keeps the richest durable payload, carries forward the newest open/update time, and emits tombstones for every discarded id. The reading-view vocabulary drawer can resolve a source sentence against all saved articles. Vocabulary created inside a public recommendation also stores an optional durable `sourceArticle` reference with the public id and title, so a source jump can load the recommendation directly without a local save; legacy entries without that field lazily scan the server-rendered public inventory, then persist the discovered reference through normal vocabulary sync. Availability checks use explicit references and cached exact-body matches; fuzzy fallback builds a bounded sentence/term index once per article and yields between fallback articles instead of tokenizing the current article plus every saved article during render. A successful jump into a saved article touches its recent-read time and persists the first aligned viewport anchor directly into lightweight `reading_state`, bypassing ordinary dwell/travel thresholds without pushing the complete saved-article list back through `ReaderView`. When the match is outside the current article, `HomeClient` starts a fresh reader session with that article before highlighting the source, preventing stale article state from consuming the jump request. Long articles keep distant blocks as layout-identical plain text and mount interactive word nodes only for a settled viewport window. At initial render, resize, or scroll settlement, a binary search over the ordered block tops selects the blocks intersecting the viewport plus a 320px margin; replacing that article-scoped window dehydrates blocks that were left behind, so reading through a long article cannot accumulate the whole token tree. Any document scroll first opens a block-interactivity transaction. During the transaction no DOM scan, observer callback, subscriber notification, or token mount/unmount runs. Ordinary scrolling commits only after 180ms without another scroll event; a large scrollbar-style jump keeps the transaction open for 1.8 seconds so a main-thread pause cannot be mistaken for release and restart hydration in the middle of a drag. Only the affected memoized text/table blocks subscribe to the final window replacement and receive interruptible transition-priority updates. Pointer/touch entry or a source jump can still reveal one target block urgently without waiting for settlement. The top-level `ReaderView` therefore does not rerender on every scrollbar-thumb position, and no `IntersectionObserver` tracks every article block during continuous movement. A source jump activates only its target block before alignment. Every token id is scoped by its source block before entering selection, lookup and highlight maps; repeated local token numbers in different paragraphs therefore cannot select or paint multiple unrelated words. Plain and interactive forms use the same typography and real block height rather than `content-visibility` intrinsic-size estimates, so hydration does not change wrapping or the scrollbar. Reading-progress capture still resolves the current block at a settled reading line instead of scanning every prior block on every animation frame, while account-sync serialization is deferred to browser idle time and a short scroll/pointer/key quiet window so background persistence does not contend with active reading. Undo, redo, edit entry and save capture a block-relative viewport anchor before applying a snapshot and restore it in layout phase; metadata-only parent updates do not replace the active imported article tree. Source jumps carry a monotonically increasing request id, wait for the article media gate and every vocabulary/menu scroll lock to release, then retry until the target tokens exist; the generic reader-entry scroll reset must not run for a pending source jump. The initial target highlight is derived before first paint, and the matched block is centered instantly without animating across the document. Recommendation opening starts its data request before the cover animation finishes and primes the leading inline image through a shared bounded cache. Reader entry gates only on that first image for at most 1.6 seconds; it is eager/high priority, while later images remain lazy/low priority. Imported image blocks persist source width and height when available so the browser reserves their aspect ratio before download; legacy blocks without dimensions receive a 4:3 fallback ratio until their natural dimensions arrive, preventing a lazy image from beginning at zero height. A source jump never promotes every preceding image to eager loading; an image that loads naturally during the short alignment window may correct the target center without changing Reader state. Location highlighting is presentation-only: the source sentence receives a quiet highlight and the selected vocabulary word or phrase receives a stronger amber underline treatment without focus changes, article edits, history entries, or cache-key changes.

## Translation Flow

Sentence context uses punctuation-aware boundary scanning so periods inside common abbreviations, names and initials, numbers, numbered labels, domains, email addresses, and similar dot-joined tokens do not split lookup context prematurely.

Word and phrase lookups send only the selected text plus current, previous, and next sentence context to `/api/explain-word` and, on cache misses, `/api/explain-word-stream` in parallel. The stream uses fixed labels for lemma, current-form phonetic, part of speech, difficulty, meanings, sentence translation, usage, collocations, and examples. `ExplanationPanel` parses those labels into one progressive visual tree. The streaming route emits an internal completion boundary immediately after the last display field and before usage bookkeeping closes the response. At that boundary, `lib/explanationDisplay.ts` validates the complete visible result, records `phoneticFor` as the exact selected word or phrase, derives the local Anki fallback fields, caches it by `word + sentence`, and immediately enables vocabulary, copy, and sentence-question actions. Structured and standalone dictionary responses follow the same ownership rule: IPA belongs to the exact selected/query form, never implicitly to `lemma`. Display, CSV, vocabulary and Anki exports use `currentFormPhonetic`; legacy entries without an ownership marker may reuse IPA only when `word` and `lemma` are the same normalized form. When they differ, the ambiguous old IPA is hidden until regeneration rather than being relabelled. The interface renders `原型` and `当前词音标` on separate rows, while pronunciation controls always receive the visible current word. Those actions never wait for usage bookkeeping or the parallel structured request. When the structured response arrives, its hidden/durable fields such as Anki metadata merge with the stream's visible authority without replacing what the user already saw. Cache replay formats the merged fields back into the same fixed-label text, preserving content, order, spacing, and wrapping. `scrollbar-gutter: stable` prevents action controls from triggering width reflow. Collocations include parenthesized Chinese translations. Repeated taps do not restart an in-flight lookup; the circular regenerate control forces a new result and, when the same `word + sourceSentence` exists in vocabulary, replaces its generated fields while preserving id, creation time, and Anki import status. Collapsing the mobile explanation sheet, switching away from explanation, leaving Reader, or closing the standalone dictionary aborts unfinished browser work immediately. Because a fully buffered POST may not expose a proxy-side disconnect through `Request.signal`, the client also sends the shared random action id to bounded same-origin `/api/lookup-cancel`; a process-global registry aborts every structured/stream controller for that id, including a request that registers just after the cancellation arrived. If the structured response becomes invalid while its stream peer is still active, provider reporting waits for that peer to settle: an intervening close cancels the whole action without a report, while normal stream completion confirms that the completed malformed structured response is a genuine `provider_parse_error`. This path refunds the shared action as `cancelled/client_cancelled` and never creates an Admin error or alert.

Full-article translation uses one parent `/api/translate-article/start` quota action and normally one streaming `/api/translate-article` provider execution, then closes through `/api/translate-article/finish`. The monthly `full_article_translation` counter therefore changes once per clicked new job, not once per paragraph or provider batch. Merely opening the translation sidebar, switching tools, restoring partial data or reopening a completed exact-version cache creates no action. Explicit regeneration creates another action and keeps the old translated blocks visible until replacements succeed. The client sends up to 80 target blocks / about 24,000 target characters in one batch. When the target is the complete article, it is also the context and is serialized only once; missing-block retries or oversized later batches carry the separately bounded full context of up to 240 blocks / 64,000 characters. The server recognizes completed JSON objects incrementally across arbitrary chunks, including concatenated objects, fenced output, arrays and a wrapped `translations` object, instead of requiring the model to honor physical JSONL newlines. DeepSeek Flash may also return the Chinese value under the exact requested block-type key (`heading`, `paragraph`, and so on) despite being asked for `translation`; the route accepts that id-aligned key only and never guesses from unrelated string fields. It relays one NDJSON paragraph event as soon as each block object closes, preserving paragraph-by-paragraph reveal while removing the old repeated-full-context request for every paragraph and the initial target/context duplicate. Exceptionally long articles use a small number of bounded batches. Completed blocks are cached immediately, and a transient stream failure retries only missing blocks without deleting prior progress. The retry countdown changes every second, repeated zero-progress streams stop after three attempts, and user copy reports zero or partial completion factually. Each upstream batch records its own tokens, cost and outcome; the default translation model is `deepseek-v4-flash` unless `DEEPSEEK_TRANSLATION_MODEL` explicitly overrides it. If an Admin candidate already has a complete current-body translation cache, publication uploads it automatically. Candidates expose no separate translation-entry or paste UI.

Published curated translations use the same body-derived cache key as the Reader. Admin exposes one direct upload action: no complete current-body translation reports that none exists, an exact existing upload reports that it is already present, and otherwise the current complete cache is uploaded immediately. The server recomputes blocks and rejects any cache key or block set that no longer matches the stored body; stale rows are removed when a replacement is accepted. A member's first click for a published article id plus exact cache key uses a deterministic per-account action id, consumes one `full_article_translation` action, returns the stored blocks and finalizes as `cached` without refunding that deliberate charge. Replays of the same action are idempotent. It creates no `usage_executions`, so model cost is zero. Editing the source body changes the cache key, hides the old translation and requires Admin confirmation/upload for the new version.

Saved-article summary generation uses the independent monthly `article_summary` action. First save persists the article immediately and calls `/api/summarize-article` only when no valid summary exists and the body is at most 6,000 characters, then saves the result; longer bodies remain saved without requesting a summary. Exhausted summary allowance and other summary failures also leave the saved article intact and produce a saved-without-summary status instead of turning the whole action into a save failure. Repeated saves reuse a valid summary and the control remains disabled as `已保存`. Summary regeneration is intentionally absent from both Reader UI and the route contract. Failures refund the action while still recording failed provider execution evidence when a DeepSeek request was actually attempted.

## Homepage

Reader night mode is a shared surface system, not a body-background inversion. `app/globals.css` defines the reader canvas, panel, raised/soft surface, primary text, muted text, accent and boundary ramp; the same ramp applies to the article, explanation and translation sidebars, vocabulary drawer, account/guide Menu previews, inputs, tables, notices and image-viewer controls. `WordToken` exposes explicit selected, highlighted and source-target states so hover, selection and jump highlighting keep paired foreground/background colors instead of inheriting the daytime pale fill. `PronunciationButtons` and `ArticleTranslationPanel` likewise expose semantic control and state classes for default, hover, focus, playing, regenerate, retry, progress, warning and disabled states. Reader panel tabs expose `data-active`, so their night colors no longer depend on matching Tailwind class strings. CSS-module surfaces that own their own palette, including `HomeOptionMenu`, `ReaderToolbar`, `BookDictionary`, `GuidePageContent`, `HomeRedesign` and vocabulary learning details, define night rules after their daytime declarations so the cascade cannot restore low-contrast daytime text or cards. The guide keeps one paired palette in both its standalone route and embedded Menu preview; its nested Anki assistant has explicit dark step surfaces. Desktop embedded dictionaries and mobile compact dictionaries share the same result, example, disabled and empty-state ramp. Every future UI change must ship day and night colors together and verify default plus interaction states at practical WCAG AA: 4.5:1 for normal text and placeholders, 3:1 for large text and non-text controls.

`ArticleInput` and `ImmersiveHome` retain legacy/shared entry behavior, but neither is a new design baseline. `/` is the canonical homepage; reusable article import, saved-article, vocabulary, account and `ReaderView` contracts remain shared beneath its presentation layer.

`app/page.tsx` server-loads public article summaries plus the independent homepage-curation setting and renders `HomeClient`; legacy `/home-v2` requests redirect to the root. `HomeRedesign` is the current real presentation layer while `HomeClient` owns the durable boundary: active article state, URL/paste import, recommendation detail fetch and prefetch, cache preload, saved articles, vocabulary-source jumps, reader transition and `ReaderView`. Publishing, topic placement, recommendation-pool membership and the optional recommendation feature remain separate. Curation version 2 preserves the five category arrays and adds `recommendationFeaturedId`; version 1 reads migrate their former first recommendation into that field. `lib/homepageRecommendations.ts` treats the Admin recommendation pool as primary, then fills a ten-article window from all published inventory when the pool is sparse. Without preferences, the optional recommendation feature/manual order leads and fallback ties use a stable Shanghai-day hash. With preferences, interest and audience-stage scores rank both manual choices and fallback supply; manual entries win equal-score ties and are not discarded solely for an interest mismatch. Covered fallback cards precede coverless equivalents. The result always exposes up to ten cards before member “显示更多”, fixing the former `1 + floor((n - 1) / 3) * 3` formula that reduced two or three available articles to one visible card. Recommendation image observers reset every mounted card, wait for a painted keyframe, then observe the featured card, grid cards and newly revealed final card alike; no already-visible card may silently skip its entry motion. The homepage standalone dictionary uses two explicit responsive contracts: desktop renders the Reader-sized fixed left window (about `340×560` at the standard wide viewport) with independently scrolling results, while mobile renders the full-width bottom sheet capped by its mobile height rule. Neither restores a draggable position or size from browser storage, and a change to one contract requires a regression check of the other.

`HomeClient` also owns Reader history semantics. The visible “返回首页” control skips the current tab's entire Reader history depth and restores the original root-home snapshot; browser, mouse-side and system Back pop one Reader session at a time. Opening a published recommendation immediately establishes recent-reading ownership. An exact saved-body match is touched and receives progress directly; otherwise an authenticated account receives a temporary-reading record that retains the public article reference across refresh. On save, ownership moves to the new saved-article id without losing the current viewport or the reviewed public summary/cache identity. `ReaderView` preserves the exact document `scrollY` while switching into or out of in-canvas edit mode; semantic block anchors remain reserved for reopening saved content whose layout may have changed.

The current implementation still renders `BookHome`, whose desktop controller combines a closed cover, Ballpit scene, chapter spreads, scroll-driven `CurvedPageTurn` snapshots, idle settle and nested wheel-boundary handling. Those mechanisms explain the code in the audited worktree, but the accepted product direction supersedes them: retain the cover and Ballpit as a brand/IP surface, remove all cover/inner page turns and scroll-driven turning, and let a cover or primary-action click reveal real recommendations and reading entry quickly. The old page-flip geometry, timing constants and wheel arbitration are therefore migration/removal concerns rather than protected architecture.

Do not build a parallel `/home-lab` or a static mock. Iterate on the real root homepage in a branch, with server-rendered articles and `HomeClient` callbacks connected in the first reviewable slice. Once the replacement flow is accepted and covers all required functions, remove unused `CurvedPageTurn` code, page-turn CSS, listeners, dependencies and obsolete regression rules together instead of preserving two homepage engines.

UI verification has three independent layers: technical correctness, visual fidelity to the user-confirmed reference and repeated-use product experience. Browser keyframes or a short comparison recording are required for a positive visual-fidelity claim; build/HTTP/state-machine evidence alone establishes only technical correctness. See `docs/home-v2-implementation-contract.md` for the current/target contract and validation workflow.

The standalone dictionary server recognizes each complete provider JSON object across arbitrary chunks, pretty-printed multi-line objects, fences and adjacent objects, then emits one compact event per line. Provider formatting whitespace therefore cannot make an otherwise complete lookup appear frozen or incomplete. Contextual single-word explanations apply the same completion discipline to IPA: a stream result without current-form phonetic data is incomplete, structured fallback must repair `phonetic` plus matching `phoneticFor`, and the visible durable text is rebuilt from the merged result so the repaired field cannot remain hidden behind an older stream string.

`BookDictionary` consumes `/api/dictionary-stream` as newline-delimited structured events. Each complete event mounts the matching final UI block in order, and the accumulated event model becomes the saved and cached `DictionaryResult` without a completion-time layout swap. The route accepts a short Chinese query for Chinese-to-English or the existing English word/eight-word phrase for English-to-Chinese. English keeps the existing deep-dictionary hierarchy and reader-panel presentation, including its headword, pronunciation, senses, applicable past/past-participle/present-participle forms, concrete usage guidance, three or more useful collocations, reasonable word family and synonyms, mistakes, and memory guidance; streaming output must not silently reduce this to the compact Chinese-to-English shape. The head event includes `phoneticFor`; for English input it must equal the exact query, so a lookup for `tilted` can show `原型：tilt` separately while the IPA and both audio controls remain explicitly attached to `tilted`. An `ambiguous` head may group senses under multiple `headword` values: `fell`, for example, preserves both the past tense of `fall` and the independent `fell` verb/noun instead of letting either analysis erase the other. The standalone session and durable cache schema versions changed with this invariant, preventing an older lemma-owned IPA from replaying as current-form data. Chinese remains the visible headword; candidates are grouped by part of speech before every independently pronounceable English expression shows its own IPA, register, usage note, and bilingual example, followed by one concise comparison section and optional genuine mistake warnings. The provider returns one candidate when one is sufficient and multiple candidates when common contexts require different choices; Chinese-to-English does not render English-to-Chinese collocations, word family, synonym grids, or memory tips. The homepage compact dictionary and the article reader's narrow dictionary panel share data and actions but not a scaled copy of the same Chinese-to-English layout. Only the reader panel's Chinese-to-English result uses the container-specific hierarchy: each expression, metadata, IPA, equal-width pronunciation controls, usage note, and example occupy stable vertical rows; numbered meanings keep a narrow fixed gutter. Shared history keeps four equal-width recent-query pills on one line at standard sidebar width and five in a wider container, truncating long labels with an ellipsis before the full-width expandable list. Expanded history rows expose a separate accessible delete action that removes only that lookup and syncs its deletion. English head events classify `valid`, `inflection`, `ambiguous`, or `misspelled`. Closing the standalone window, switching tools or otherwise aborting its active request is a client cancellation: usage is refunded as cancelled and no provider/site error record or alert email is created. Both directions reuse the same DeepSeek defaults, concurrency/usage accounting, history, durable cache, account sync, and offline replay; the circular regenerate action deliberately bypasses lookup cache and overwrites it only after a complete new result arrives. Saving English-to-Chinese carries verb forms into study notes. Saving Chinese-to-English uses the first English candidate only as the vocabulary and TTS identity while preserving all part-of-speech groups and the Chinese cue in `basic_cn_to_en_dictionary`; its Anki front is Chinese and its back contains the candidate expressions, pronunciation, examples, comparison, and useful warnings. Article-derived selections use a context cloze whenever the target can be located while preserving other English context; standalone dictionary entries remain the explicit basic-card exception.

Public recommended articles are fetched in the server `app/page.tsx` and passed into the client homepage as `initialPublicArticles`. Do not move this list back to a client-only `useEffect` fetch; otherwise the recommendation spread first renders without them and visibly fills them in later. Saved articles belong to the shared Menu rather than the recommendation spread.

The reading view uses the same vocabulary data but keeps the notebook as a right-side drawer so it does not cover the article workspace. Shared overlay locking is reference-counted: Menu, notebook and nested tools preserve the page's exact scroll position until the final overlay closes, while each panel keeps an explicitly sized, `min-height: 0` internal scroller. The homepage's global wheel/touch teaching locks and desktop scene snapping must ignore events from marked local-scroll surfaces, and notebook overscroll stays contained instead of reaching the page. Mobile Menu controls and panel-close affordances expose at least a 44px touch target and sit in a pointer layer above the 44px drag handle; a visible return control must never share the handle's hit layer. Viewport breakpoint changes clear stale hover/detail state and remeasure virtual rows instead of reading `window.innerWidth` during render. Vocabulary is always sorted by `createdAt` descending after normalization, deduplication, and cloud merge, so account login cannot inherit the sync table's object-key order. Entries use TanStack Virtual with stable entry keys, transform positioning, small bounded overscan, content-aware unmeasured-height estimates, animation-frame ResizeObserver batching, and live element measurement. Scrollbar dragging does not trigger compensating scroll-offset writes as new rows are measured. Only rows near the viewport mount, hidden homepage animation frames and CSS animations pause while the notebook is open, and the overlay avoids a full-screen backdrop filter. Do not reintroduce fixed oversized rows or React state updates on every scroll event; short cards should stay compact and long cards should remain fully visible.

Shared tool panels should not preserve stale interaction traces across open/close cycles. `VocabularyPanel` clears its search, preview, and expanded-detail state and scrolls its list to the top when opened or when the filtered list changes. Vocabulary rows always show IPA when available plus the original core fields; usage notes, collocations, and bilingual examples are progressively disclosed by the per-entry `显示全文` control. Rows continue to use measured content heights before and after expansion. `lib/vocabularySearch.ts` builds a sorted normalized-word index once per ordered collection and resolves prefix searches with binary bounds, so query cost scales with matches rather than total stored vocabulary. Browser TTS voice discovery and warmup are shared across memoized pronunciation controls rather than repeated when virtual rows mount. The Home Menu vocabulary preview uses fixed compact virtual rows without per-row resize observers, disables their pointer targets while the list is actively scrolling, and therefore does not replace the hover detail for every row passing beneath a stationary pointer. Parent views clear temporary vocabulary errors and Anki status when the drawer/dialog closes.

## Mobile Reader

The mobile reader keeps the article as the primary single-column surface and puts a fixed tap-only tool dock above the safe area. Explanation, full-article translation, standalone lookup, vocabulary, and lower-frequency article actions share a draggable near-full-screen sheet; switching tools changes the sheet body without moving the reading position. Opening full-article translation must not start the job automatically. Anki import controls are absent on mobile but remain available on desktop. The sheet owns its local scroll and overscroll containment, and only its compact handle/collapse control stays fixed while content scrolls. Image zoom, fit, download, and close actions appear in a bottom image-viewer toolbar after an image is tapped. Vocabulary CSV export and destructive clearing stay inside a secondary action disclosure.

Touch word selection separates reading scroll from lookup gestures. Vertical movement is treated as article scrolling and should not highlight or query a word. A tap explains one word. Horizontal movement across words or long-press selection can select a short phrase, capped at eight words.

Each new explanation resets the bottom sheet to its default half-height and scrolls the explanation content to the top. Collapsing the explanation panel should preserve the article reading position, but temporary panel state should not leak into the next lookup.

## Account, usage, and sync

In mainland production, the server-side `SUPABASE_*` names are compatibility variables for the self-hosted adapters and always resolve to the private `supabase-api` gateway. Supabase Cloud is not an active data path. The mainland image refuses to start when the runtime mode is missing or `SUPABASE_URL` is external, while `/api/connectivity` exposes only the safe `mainland_internal` marker for release acceptance.

Account sync transport uses byte-bounded response pages. A protocol-2 bootstrap captures one latest-server cursor, transfers active payloads and a lightweight tombstone index through that fixed snapshot, and persists an opaque keyset cursor plus version/hash/deletion manifest. Every later pull reads only rows newer than `(updated_at, kind, object_key)`; it does not scan the complete account history. The `preferences/homepage-recommendation-preferences` object carries the account-scoped reading level and interests; guest-scoped browser preferences never silently overwrite an existing cloud account preference during login. Automatic learning-data sync remains active on `/admin` only for the developer account so vocabulary and locally saved articles created inside the real ReaderView are durable; password-only Admin sessions have no account sync. Normal pages serialize writes both within one tab and across tabs with the Web Locks API.

The 2026-09-05 compressed-article incident added a one-time protocol-2 snapshot replay keyed by `context-reader:article-storage-recovery:20260905`. It repairs an initialized browser whose local article collection became incomplete even though older active article objects still exist in the cloud. The replay merges active objects and honors explicit tombstones; absence from local storage is never converted into a delete. The completion marker is written only after the full merge and sync succeed, and ordinary incremental cursor behavior resumes afterward.

`AccountProvider` loads `/api/auth/session`, opens the phone/password form only for restricted actions, and requires a successful final sync before explicit logout clears browser data. The server-managed refresh cookie uses a 400-day maximum age; normal authenticated access refreshes the upstream session after the short-lived access token expires and rewrites that 400-day window. Explicit logout, password/security invalidation, account disablement and browser Cookie removal remain valid session-ending boundaries. Durable local changes identify their object kind, debounce for about 800 ms, then wait for two seconds without scroll, pointer or keyboard activity and a real browser idle window before serialization. Visible tabs still check for remote changes about every 15 seconds and on focus/visibility return, but those checks are pull-only: an unchanged response does not read, parse, hash, compress, rewrite or rebroadcast the article, vocabulary and cache stores. A response containing cloud changes waits for its own interaction-quiet idle window before merging. Phone registration collects a nickname, maps the unverified mainland-China phone identifier to a reserved server-only Auth email, and stores the six-digit numeric password through Supabase's password hashing. Legacy email-link adoption remains compatible but is hidden from the current UI. The session includes the active entitlement source and dates; expired grants resolve to Free. `lib/accountSyncClient.ts` stores each article, vocabulary entry, lightweight reading state and explanation/translation cache item as an independent versioned object; opening an article or persisting a viewport anchor updates `reading_state` instead of rewriting the full saved-article body. Normal reading still advances only after the existing time, travel, forward-progress and stable-dwell gates. For ordinary saved-article entry, a rapid scan that is not followed by eight seconds of stable reading, or an eight-second stable dwell at the document bottom, writes an explicit top anchor so the next open restarts the article; vocabulary-source jumps are exempt and continue to align the exact source sentence. Cache durability does not depend on saving the article. Supabase compare-and-swap prevents stale devices from overwriting newer versions; client writes are single-flight, unique by kind plus object key, and retry after refreshing incremental server changes. The client compares normalized JSON payloads with stable key ordering and skips unchanged objects. Article conflicts resolve to one canonical article and discarded duplicate ids become tombstones; article sync must never create a visible recovery copy. The sync API also converts any legacy `-local-recovered-*` article write into a tombstone so an older open tab cannot resurrect deleted copies. After a cloud merge, only consumers of the changed kinds refresh: article/reading-state changes update the saved list, while vocabulary and dictionary surfaces ignore unrelated merges. Vocabulary versions are normalized, merged and deduplicated by word plus source sentence while preserving optional public-article source metadata; redundant recovery ids become tombstones, while a genuinely ambiguous same-id/different-identity local value is preserved in a separate local recovery store and never counted as a notebook entry. Article, reading-state and vocabulary deletions are persisted as tombstones so another device cannot silently restore them. Tombstone compaction is a future backend maintenance operation and must require a retention plus client-acknowledgement design before deletion.

For workstation-only development, `next dev` accepts only the loopback hosts `localhost`, `127.0.0.1`, and `[::1]` for local identity shortcuts. When ignored local environment configuration supplies a valid `LOCAL_DEVELOPER_USER_ID` alongside usable Supabase credentials, the request is represented as that exact Auth UUID and then passes through the normal profile, entitlement, usage, sync, and Admin checks. The browser preserves existing local content during the first transition to that UUID before normal versioned cloud merge. This does not infer developer access from a nickname: Admin still requires Supabase to report an active profile and active `admin` entitlement for the exact UUID. With no usable Supabase credentials, the loopback path instead uses a browser-local learning identity, disables cloud sync and remote export, bypasses cloud quota bookkeeping for local AI calls, and never grants Admin. Both shortcuts are disabled for production builds, `next start`, and non-loopback hosts, so neither is a deployed authorization path.

Saving an article commits the local article object and schedules account sync before requesting its generated Chinese list summary. The browser article collection is stored as `lz-string` UTF-16 data under the existing `context-reader:articles:v1` key; legacy plain JSON remains readable and is migrated on the next normalized read. This removes repeated long-form JSON overhead without changing the protocol-2 cloud object payload. Summary quota, network or provider failures therefore leave the article saved instead of rolling back the durable article record.

All cost-bearing routes use `lib/usageGate.ts`. Structured and streaming word lookup requests share `x-context-action-id`, so the quota action is idempotent while `usage_executions` stores every real upstream call. Registered-user failures are refunded and cache hits are free; guest cached lookups call `/api/usage/cache-lookup`. `public.consume_usage` is a shared database contract for every old and new metric: any migration that replaces it is first applied to a verified isolated backup restore, then `ops/mainland/verify-usage-contracts.sql` invokes it for every configured metric and repeats each action id to cover idempotency. A migration-specific test of only the newly introduced summary/translation metrics cannot establish lookup safety. Full translation, summaries, sentence questions and OCR require login. `/account/usage` is the user view; the unified `/admin` console manages public recommendations, users, ordinary-user limits, invitation codes, provider cost summaries, and feedback. Its usage summary reads every execution from the latest 30 Shanghai calendar days instead of silently stopping at 1,000 rows, groups them by Shanghai date, and returns zero-filled days as well as active days. Each day exposes execution count, input/output tokens, estimated CNY cost, failed count, and failure rate. The same rows are also grouped by product function, with full-article translation separate from article lookup, standalone dictionary, summary, sentence questions, and recommendation analysis. Cost is recomputed per DeepSeek row using its call timestamp, model, cache-hit/miss tokens and the provider's historical or current direct CNY price. From 2026-08-23 onward, Saturday and Sunday are always off-peak; weekday 09:00–12:00 and 14:00–18:00 remain peak. `DEEPSEEK_USD_TO_CNY_RATE` is retained only for the legacy stored micro-USD estimate, not the visible CNY total. The safety ceiling is 50,000 rows and is surfaced as truncation rather than a false exact total. The provider console remains authoritative because one DeepSeek account or API-key filter can include calls outside this site's execution ledger. Admin creates a random one-time code, stores only its SHA-256 hash and hint, and sees the plaintext only in the creation response. `redeem_invitation_code` locks the matching row, rejects revoked/expired/redeemed codes and active paid/invite entitlements, then atomically marks redemption and writes the fixed-duration entitlement. Admin quota rows are grouped by Chinese product meaning, batch-save the fixed metric/window pairs for each ordinary plan, and intentionally hide the developer allowance plus unconnected price settings.

The browser never receives a Supabase key. Without account infrastructure, reading and a browser-enforced ten-lookup fallback remain available, while login and authenticated high-cost features remain disabled.

## API Routes

`middleware.ts` and `lib/requestSecurity.ts` form the common request gate. They apply trusted reverse-proxy client/origin extraction, route-specific fixed-window limits, daily costly-operation limits, `413` early rejection, same-origin admin checks, request ids, and private admin cache headers. `lib/limitedBody.ts` also counts actual streamed bytes before JSON or multipart parsing, so missing or forged `Content-Length` cannot bypass route limits. `lib/costConcurrency.ts` caps simultaneous AI and OCR work per server instance and releases leases on completion, error, stream cancellation, or client disconnect where the upstream route exposes a signal.

All user-controlled outbound URL reads use `lib/safeRemoteFetch.ts`. It accepts only standard-port HTTP(S), rejects credentials and non-public/reserved IP ranges, resolves and pins the verified IP for the actual TCP/TLS connection, preserves the original Host/SNI, rechecks every redirect, and streams responses through hard byte caps. AnkiConnect accepts only local `127.0.0.1:8765` and has an eight-second timeout.

Mainland production currently fetches URL imports and crawler pages only through its own direct egress; no overseas relay is shipped. A future narrow relay has been scoped but deliberately deferred until meaningful paid revenue or user volume justifies its operating and abuse surface. If revisited, its initial contract is public static article HTML only, below roughly 100 imports per day, no cookies/login/paywall/private data or arbitrary browser execution, and the same mainland-side SSRF, pinned-DNS, body-limit and article-boundary checks remain authoritative. A network-class miss must keep the submitted URL and suggest pasting the article text; it must not masquerade as an unsupported article or developer fault.

- `/api/public-articles`: lists public recommended articles for clients and service-worker caching. The homepage does not depend on a client-side call for first paint.
- `/api/public-articles/[id]`: reads one public article plus its preloaded word explanations and full-article translation caches.
- `/api/auth/*`: registers/signs in phone + numeric-password accounts, retains legacy email OTP and hosted-session adoption, reads/refreshes the current account session, and logs out through server-managed cookies.
- `/api/account/sync`: reads and compare-and-swap merges versioned account objects; `/api/account/export` returns the member's profile, synced objects, and usage-action history.
- `/api/usage/cache-lookup`: completes an idempotent cached guest action; the current `finalize_usage` contract refunds its reserved unit, so cache hits do not consume either guest lookup pool.
- `/api/account/profile`: updates the authenticated account's nickname and optional reading profile with bounded, allow-listed fields. The current UI edits English level and interests and can clear demographic fields.
- `/api/account/invitation-code`: redeems one hashed, single-use invitation code for the current signed-in account; `/api/admin/invitation-codes` creates, lists and revokes codes under server-authorized Admin.
- `/api/admin/homepage-curation`: server-authorized Admin read/write surface for the independent homepage showcase order. Publication status and homepage placement remain separate.
- `/api/admin/*`: handles public article listing/publishing/deletion, account/quota administration, private feedback listing/status/deletion, and detailed error-report review. `lib/adminAuth.ts` accepts a server-verified user whose entitlement is `admin` or the signed legacy password-admin cookie; client-side menu visibility is never the authorization boundary. Writes still require same-origin requests.
- `/api/import-url`: fetches bounded public HTML through the pinned-DNS safe path and parses it in a server-side DOM without executing page scripts. The extractor removes explicit hidden/inert/ARIA-hidden content plus high-confidence navigation, advertising, sponsored, newsletter, sharing, comments, related-card, author-card and embedded media-control subtrees. It also drops raw iframe/embed controls, generic transcript/download UI, standalone image credits and trailing editor/legal boilerplate. It compares Mozilla Readability output with site-semantic `articleBody`/article/main/content candidates, preferring the narrower readable result unless a clean structural candidate contains materially more substantive text or preserves tables/images Readability lost. This conservative comparison protects completeness instead of treating any single heuristic as authority. It then applies the shared block-level trailing boundary, including explicit `-end-` markers after sufficient article content. The returned blocks preserve headings, paragraphs, ordered/unordered list level and ordinal, quotes, figure captions, meaningful inline images, `sup`/`sub`, and bounded structured tables with header scope and row/column spans. The route returns this text and structure without waiting for image storage. Link-dense repeated cards and linked teaser images are omitted, while ordinary inline citations remain. A standalone advertisement label is retained only when the article is substantively about advertising. Fully dynamic pages, login walls and strong anti-bot challenges can still fail because the importer deliberately does not run arbitrary remote JavaScript.
- `/api/ocr-image`: extracts text from one uploaded image up to 8MB.
- `/api/ocr-image-layout`: detects word boxes for multipart uploads, data URLs, or remote image URLs and returns percentage coordinates plus line context.
- `/api/ocr-image-url`: extracts text from a remote image URL. The route is enabled, but the URL-import reader does not call it automatically while its OCR gate is off.
- `/api/article-images/localize`: rate-limited image localization. Authenticated calls lazily repair external URLs inside historical saved articles and preserve failed sources for retry; an anonymous `freshImport` call requires the short-lived HMAC token issued with that exact article URL and image-source set, rewrites successful sources to bounded first-party WebP assets and drops only failed image blocks.
- `/api/download-image`: fetches and validates a remote image up to 20MB and returns it as a short-lived private attachment.
- `/api/explain-word`: sends only selected word/phrase and sentence context to DeepSeek.
- `/api/explain-word-stream`: sends the same selected context to DeepSeek and streams fixed-label Chinese text whose completed visible fields are merged into the durable explanation.
- `/api/lookup-cancel`: accepts only a bounded same-origin action id and aborts the matching in-process explanation or standalone-dictionary controllers without creating an error report.
- `/api/dictionary`: accepts a Chinese word/short phrase, one English word, or an English phrase of up to eight words, consumes one `lookup_generation` unit, and returns a detailed bidirectional context-free dictionary result. It uses the same DeepSeek defaults, request-size limits, execution ledger, estimated-cost recording, and AI concurrency guard as the other generated lookup paths.
- `/api/translate-article`: translates sanitized article text blocks to Chinese for the full-article translation sidebar. The client normally sends one bounded multi-block target batch and adds separate full-article `contextBlocks` only for a missing-block retry or a later oversized batch. The route briefly queues behind the in-process cost cap, passes a privacy-safe hashed `user_id` for provider scheduling isolation, and returns structured retry codes that distinguish temporary provider pressure from quota, balance, and configuration failures.
- `/api/summarize-article`: summarizes saved articles for the homepage list.
- `/api/ask-sentence`: answers follow-up questions about a selected sentence.
- `/api/pronunciation`: validates a bounded English word or short phrase, reads a private content-addressed MP3 cache, and calls Volcengine TTS only on a miss.
- `/api/anki/*`: checks/creates Anki helpers, while browser-side AnkiConnect is still required for local note import.

DeepSeek-backed routes send `thinking: { type: "disabled" }` in completion requests. Contextual word explanation, its sentence translation, and standalone dictionary use `DEEPSEEK_LOOKUP_MODEL` and default to `deepseek-v4-flash`; this lookup-specific choice is independent of the shared `DEEPSEEK_MODEL`. `DEEPSEEK_TRANSLATION_MODEL` takes precedence for full-article translation, whose blank/default value is also Flash. Contextual explanation, its progressive stream, and standalone dictionary treat HTTP 429/5xx responses and pre-stream transport failures as retryable. The default Flash lookup path has no automatic same-provider alternate model. If operations explicitly set a Pro lookup primary while leaving `DEEPSEEK_FALLBACK_MODELS` unset, the existing Pro-to-Flash fallback remains available; any explicitly configured fallback list, including an empty value, overrides that behavior. Structured word explanations additionally retry one transient transport failure, timeout, HTTP 429/5xx response, or JSON-mode empty response per profile before moving to the next profile; authentication and other non-retryable HTTP errors fail immediately. Admin diagnostics distinguish `provider_http_error`, `provider_timeout`, `provider_transport_error`, `provider_empty_content`, and genuine `provider_parse_error` reports. An upstream fetch aborted by either the direct request signal or `/api/lookup-cancel` instead throws `ClientRequestCancelledError`; `/api/explain-word` handles it before the provider-report branches, refunds it as cancelled, and returns the internal 499 response only if the disconnected client can still receive a response. A secondary `DEEPSEEK_FALLBACK_BASE_URL` may still provide a separate key/model, and sentence questions use the configured fallback model list. The word explanation route sends compact `w/s/p/n` JSON keys to reduce request tokens; the full-article translation route accepts target article blocks plus optional full-article context blocks and sends compact `[id,type,text]` tuples to DeepSeek while preserving id-aligned JSON output.

## Anki Templates

`lib/ankiTemplates.ts` defines the Context Reader cloze and basic note types. The import flow calls `ensureModel`, so existing note templates and their `AudioUS`/`AudioUK` fields are updated before new notes are added. Article-derived entries use a context cloze whenever the selected target can be located in the source sentence and other English context remains after replacement; short words and function words such as prepositions, adverbs, conjunctions, pronouns, and auxiliaries are not downgraded merely because of their length or part of speech. The basic CN-to-EN fallback is reserved for structural failures such as a missing source sentence, a target that cannot be located without rewriting the sentence, or a target that covers the entire sentence. Cloze-card front prompts are generated locally in `lib/ankiData.ts` from the durable explanation's exact `contextMeaning`: only that word-or-phrase translation appears after the large gap, with no basic meaning, sentence translation, fallback, or added label. Card backs prefer attached cloud-generated US/UK MP3 media and use native `en_US`/`en_GB` TTS only when the matching media field is empty. Standalone `basic_en_to_cn` notes keep an English-only front and render a complete Chinese study back. Standalone `basic_cn_to_en_dictionary` notes reverse only the recall direction: the front is the Chinese query and the back leads with the English expression while preserving the same IPA, pronunciation, examples, and structured learning details.

`addVocabularyNote` retries transient pronunciation failures, then passes both base64 MP3 attachments to AnkiConnect, which stores them as deterministic `[sound:...]` media references. The note is created only after both recordings are available, so every successful new import owns the same US and UK cloud audio as the website; a persistent pronunciation failure leaves Anki untouched and can be retried later. Existing legacy cards are not bulk-upgraded. Desktop Anki then synchronizes imported files through normal AnkiWeb media sync for AnkiMobile and AnkiDroid. The flow also tries to set the target deck config's `autoplay` option to `false`; if an older AnkiConnect/Anki combination cannot save it, note import still proceeds and the user can turn off autoplay in Anki deck options.

Anki import is idempotent across interrupted browser sessions. The model's first field is the invisible stable vocabulary-entry key `ContextReaderId`, while `CreatedAt` plus `Word` remains the recovery signature for older cards. Notebook entry and batch import reconcile every locally missing receipt against all `context-reader`-tagged Anki notes, independent of the currently configured deck. `addVocabularyNote` also checks immediately before creation, disables Anki's duplicate allowance, and rechecks after an ambiguous `addNote` failure. A matching existing Note ID is persisted back into the vocabulary object and normal account sync instead of creating another card; no automatic Anki deletion or merging is performed.

## Public Recommendations

The shared imported-article normalizer keeps one heading, strips a headline repeated as the prefix of an early standfirst, removes only adjacent exact normalized text duplicates, and reindexes blocks. Named, decimal, hexadecimal and up to four layers of ampersand-escaped HTML entities are decoded to Unicode in extracted, mapped public and browser-local saved articles. Raw HTML preprocessing unwraps only ampersands that introduce nested entities, never all entities, so prose such as escaped `<iframe>` remains text rather than becoming structural markup.

Public articles are stored in the active PostgreSQL tables created by `docs/public-articles-supabase.sql`; the SQL and API names remain Supabase-compatible even on the mainland self-hosted backend. The Admin intake surface treats browser-local saved articles, pasted text, and URL import as equal entry modes in one candidate editor. URL intake reuses `/api/import-url`, preserves meaningful inline images, and receives description plus cover candidates. `/api/admin/article-classification` uses DeepSeek when configured and local readability/topic rules as a fallback. It produces a Chinese summary, Chinese learner difficulty, CEFR reference, audience stages, interest topics, reading time, timeliness, and review notes. Those classification fields are displayed as system-owned output rather than editable admin choices.

Candidates reuse `public_articles` rows with `published=false`. Recommendation metadata is stored in `imported_article.recommendation`, including optional cover URL and attribution, homepage category and optional rejection timestamp, so existing production tables do not need a destructive schema migration. Rejected rows are hidden from the active queue, remain restorable, and continue participating in crawler URL deduplication. Candidate intake deduplicates canonical source URL, normalized title and stable body identity across active, rejected and published rows; crawler result accounting distinguishes an existing match from a newly created candidate. `lib/articleContentSanitizer.ts` also trims recognized trailing website sections when old remote-URL candidates are mapped for Admin preview and immediately before publication; publishing persists the cleaned body and blocks, while plain pasted candidates are untouched. Candidate saving now immediately resolves supported CDN wrappers, fetches the candidate cover and every retained remote body image through `safeRemoteFetch`, rejects invalid or oversized bodies, uses Sharp to normalize successful media to bounded WebP files, and stores them under SHA-256 content-addressed keys in the active public `public-article-covers` Storage bucket. Media state is resolved once across Admin, homepage and Reader: if the dedicated cover is unavailable but a retained body image succeeded, the first body image becomes the homepage cover; if a cover exists but no independent body image survived extraction, Reader inserts that exact cover after the article heading; when both exist, Reader keeps the editorial image sequence and does not insert a duplicate cover. Only an article with neither source is an intentional text edition, which remains publishable and appears after the image-safe collapsed showcase. A failed body image block is omitted while all English text remains publishable. `ops/mainland/backfill-leading-cover-images.sql` remains historical migration support for rows repaired before this runtime rule. The same direct-first, server-side ingestion fallback used by ordinary URL imports applies to public media; `static.time.com` uses the fallback first because direct mainland access is known to time out. No public or saved article receives a proxy URL. `/api/admin/article-covers` uploads reviewed files and exposes an authorized maintenance action for selected or all legacy candidate and published media; `ops/mainland/repair-public-covers.py` invokes that action without printing credentials, also persists the body-image cover fallback for legacy rows, and reports safely omitted images separately from unexpected article-level failures. `/api/admin/saved-article-images` and `ops/mainland/repair-saved-article-images.py` perform a compare-and-swap migration of active synced saved-article objects: they preserve article ids, timestamps and content, advance the server version, and change only successfully localized image sources so connected clients receive the repair through protocol 2. Homepage text editions use a deliberate source-and-summary composition; rare first-party runtime failures render a quiet source-labelled fallback instead of browser broken-image UI. Candidate and published rows mount the same `ReaderView` used by normal reading. Admin reading wraps it with a fixed 330 px, independently scrollable metadata inspector and passes that desktop viewport inset into ReaderView; the fixed explanation/translation/dictionary rail, including its mode buttons, is positioned from the remaining reader viewport rather than the full browser viewport. Its optional `onArticleEditCommit` waits for the Admin candidate/public API to persist body and structured-block edits before closing edit mode; failures remain visible in the existing Reader status area. Title, summary, classification, and cover stay in the metadata editor. Published rows expose a direct deletion action that also removes stale homepage-curation references. Publishing and homepage-curation writes invalidate the root route and recommendation cache immediately. Existing explanation and full-translation caches still use `article_id + cache_key` rows in `public_explanations` and `public_article_translations`.

`lib/discoveryStore.ts` stores the administrator-controlled website registry in server-only `account_settings.recommendation_discovery_sites_v2`; `lib/discoveryDefaults.ts` groups the legacy RSS list by website and supplies disabled, unverified additions. Every website owns its enabled flag, 0–10 daily candidate target (default 2), up to six HTTPS RSS/Atom feeds or a specifically adapted index, topic labels, source-purpose hint and verification samples. Changing an address invalidates its server-owned verification; enabling requires recent verification of publishing cadence plus two readable full-body/image samples. `lib/recommendationFeed.ts` reads the newest unique permitted URLs and original publication dates, not feed update timestamps. `lib/crawlerRobots.ts` respects robots exclusions and bounded crawl delays, without bypassing challenges or login walls. Cadence checks require a publication within three Shanghai business days, so a weekend does not falsely retire a weekday publisher, and a recent typical gap no larger than three days; dormant sources remain backups. The crawl reuses `/api/import-url`, the shared boundary sanitizer and narrow publisher profiles. Candidate screening requires complete English reading material of at least 401 words for every source, including dedicated learner sources, a readable image at least 300 by 150 pixels, no subscription/sponsorship flags, successful quality review, non-specialist science, no near-duplicate title/body and reliable publication dates within seven days for news/business. The actual text determines difficulty: learner-source labels never force CET-4. Image verification uses the same direct-first, bounded ingestion fallback as final first-party localization; image or quality failures still skip the candidate rather than weaken the automatic gates. Manual intake and existing text editions retain their separate review behavior. See `docs/candidate-discovery-controls.md` for source evidence and remaining rollout limits.

`lib/recommendationAutomation.ts` retains the enabled flag, Shanghai start time and compatibility status API; the reported daily quantity is the sum of enabled website targets, not a global ten-article cap. `lib/discoveryRunner.ts` handles one website per five-minute server wake, with at most three article attempts in a batch and a three-minute check before starting another article. The durable Shanghai-day ledger records created count, visits, attempted URLs and skip reasons per site. Target two permits at most three visits per day; larger targets receive a bounded adjusted visit limit, with at least 30 minutes between visits. Scheduled and manual actions share both quota and a database compare-and-swap lease; persisted article identities reconcile interrupted runs. Exhausted sites report shortages, never repeat or publish articles to fill a quota. Only completion of the daily finite queue sends a scheduled result email. `GET /api/cron/recommendations` still requires the server-only cron secret; the mainland systemd timer, not a browser or workstation, performs the wakes. `GET/POST /api/admin/discovery-sources` manages sites, verification and bounded scans; all reads require Admin and mutations require same origin. `GET/PATCH/POST /api/admin/article-crawler` retains schedule/status, run-next and test-email compatibility. No data-table migration is needed.

The three public-content tables enable RLS and revoke all direct table privileges from `anon`, `authenticated`, and `PUBLIC`. Only the server-side service-role path reads or writes them; applying the SQL to the real Supabase project is part of deployment, not merely a documentation step.

Far-right candidate and published drawers support search, category and difficulty filters and open any row into the Reader; the candidate drawer also exposes restorable rejection history. One-step URL intake imports, classifies and saves before opening the new candidate. Active candidates keep Shanghai-today additions first and newest first. `lib/clientErrorReporting.ts` is the user-facing error boundary for browser requests. It preserves explicit 4xx input/auth/quota explanations, distinguishes a confirmed offline browser from an otherwise unreachable site, and converts 5xx failures into a maintenance message with a traceable id. Unsupported standalone dictionary input is rejected before network work: mixed-language input, overlong Chinese queries, and whole sentences receive direction-specific guidance before any request. Network and user-input failures are not stored as product bugs.

`lib/serverErrorReporting.ts` and `lib/errorReportStore.ts` persist site, provider, configuration, and client-processing faults as deduplicated private JSON under `errors/YYYY-MM/` in the feedback bucket. Each record includes operation, endpoint, user-facing and technical messages, stack, status/code, safe metadata, browser/user identity when available, deployment version, occurrence count, resolution state, and email-delivery state. The record is written before SMTP/Resend delivery; repeated email for the same fingerprint is suppressed for fifteen minutes. `/api/error-reports` is bounded, same-origin, and rate-limited for client-only failures. Only `/api/admin/error-reports` can list, update, or delete records.

The Admin layout is an explicit Reader mode rather than an inference from `desktopViewportInsetLeft`: ordinary desktop reading also reserves a navigation inset and must keep its reading shortcut rail and normal content geometry. During an Admin body save, the server result is merged only after Reader finishes its edit commit, so the live editing DOM and its captured block anchor are not replaced mid-request. Progressive long-article tokenization is cached per unchanged block, and background reading-progress persistence does not refresh the active Reader tree; both rules keep scrolling work bounded as the reader moves deeper into an article.

## Offline Behavior

The production app registers `public/sw.js` as a service worker. After the site has been opened online once, the cached app shell can reopen offline. Public article API responses use network-first caching, expire after seven days, and are capped at fifty entries, so public articles that have already been loaded can reopen offline without growing an unbounded or indefinitely stale cache.

`AccountProvider` separates server authentication from offline local access. Every successful authenticated session writes a minimal `context-reader:last-account-session:v1` snapshot containing only the user id, nickname, and verification time. A failed `/api/auth/session` request, an explicit browser `offline` event, or a server-side account-service `503` changes the client to offline mode, removes all server-authorized account state, and reopens local data only when that snapshot exists. The UI keeps an always-visible offline banner and the Menu labels the identity as offline. The snapshot must never restore plan, usage, Admin visibility, or authorization for any API route.

An offline remembered account can open, save, and edit browser-local articles, read and modify its local vocabulary, and replay cached explanations, standalone dictionary results, and full translations. Those local mutations continue to emit the existing account-data events and sync after the server session is verified again. New AI explanations, standalone dictionary generation, full-article translation, URL import, feedback submission, article summaries, cloud sync, and usage reads require network access and must show an offline-specific message instead of opening a login prompt.

## OCR Provider Framework

`lib/visionOcr.ts` provides both plain-text extraction and layout-word detection. It supports `OCR_PROVIDER=zhipu` with `ZHIPU_API_KEY`, `ZHIPU_BASE_URL`, and `ZHIPU_OCR_MODEL`, and `OCR_PROVIDER=openai` with `OPENAI_API_KEY` and `OPENAI_OCR_MODEL`. If `OCR_PROVIDER` is omitted, the provider layer prefers Zhipu when `ZHIPU_API_KEY` exists, otherwise OpenAI when `OPENAI_API_KEY` exists.

The OCR routes and provider code remain dormant for compatibility and possible future work. No current user-facing page exposes OCR: both `components/ArticleInput.tsx` and `components/ReaderView.tsx` keep `IMAGE_OCR_ENABLED = false`. Re-enabling either path is a separate product decision that must account for request volume, provider reliability, persisted block metadata, public/admin replay, and a complete user-facing copy review.

## Design

The reading workspace keeps the quiet utility treatment: no global black nav, compact readable surfaces, and restrained core controls. The homepage may use the accepted cover/Ballpit identity and a reference-led recommendation transition, but it must reveal real reading entry quickly and must not reinterpret ordinary wheel or touch scrolling as page turning. Expressive homepage motion never enters the article reader. Exact visual language remains an open redesign decision until reference comparison and repeated-use acceptance are complete.
