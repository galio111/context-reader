# 2026-09-22 生产容量边界实测

## 结论

按用户要求，出现繁忙、失败或明显卡顿即判定该档不通过，不以服务器崩溃为边界。此次已找到三个公开路径的体验边界；不是完整网站容量认证，也不能直接换算 DAU。

| 场景 | 实测结果 | 判断 |
| --- | --- | --- |
| 1 个冷启动资源下载 | HTTP/1.1 3.86 秒；HTTP/2 4.08 秒 | 在 5 秒预算内，但余量小 |
| 2 个同时冷启动资源下载 | HTTP/1.1 两轮最慢 6.82、7.17 秒；HTTP/2 分别 5.50、7.00 秒 | 不通过 |
| 10 个同时读取公开文章 | 最慢 1.06 秒 | 本轮通过 |
| 20 个同时读取公开文章 | 最慢 1.28 秒 | 本轮通过 |
| 40 个同时读取公开文章 | HTTP/1.1 两轮最慢 2.93、2.94 秒；HTTP/2 2.46 秒 | 三轮均在 3 秒预算内；不能认定可长期维持 |
| 64 个同时读取公开文章 | HTTP/1.1 两轮最慢 5.12、4.71 秒；HTTP/2 5.07 秒 | 三轮均不通过 |
| 8 个同时真实 AI 词典请求 | 8/8 成功；首段 0.81–1.42 秒；全部完成 4.36–6.82 秒 | 本轮通过 |
| 12 个同时真实 AI 词典请求 | 8 成功、4 返回 HTTP 503 / local_concurrency | 不通过，失败率 33.3% |

40 是本次文章接口已测通过的最高档，64 是已测失败档；41–63 未细分。AI 配置为同一进程共用 8 个名额，12 请求实验验证了 8 个执行、4 个拒绝。不要把这些数值写成可承载在线人数，也不要沿用先前 200–500 DAU 的粗略估算作为实测结论。

## 对象与方法

- 站点：`https://context-reader.com`。每轮检查 `/api/connectivity` 的 `backendMode: mainland_internal`。
- 所有轮次 releaseId：`20260921T083200`；parentReleaseId：`20260921T082100`。
- 活动路径前后均为 `/opt/context-reader-releases/20260921T083200`。没有发布、调参、重启或关闭限流。
- 测试时间：北京时间约 15:02–15:09。单台 Windows 开发电脑通过公网访问正式域名；没有绕过 Caddy，也没有伪造用户来源 IP。
- 标准：普通文章接口任一请求完整下载超过 3 秒；冷启动核心资源完整下载超过 5 秒；AI 首段内容超过 5 秒，或 HTTP 错误/流中错误/缺少结束事件，均视为该档不通过。标准是本轮操作性定义，不是用户浏览器体验评分。
- 阶梯式短时突发；找到失败档后不继续向上施压。HTTP/1.1 边界重复，并以 HTTP/2 交叉核对。真实 AI 共 25 次请求，其中 21 个返回完整 done，4 个为本地并发拒绝，没有 HTTP 200 内嵌错误。
- 每个 AI 请求是独立游客，会留下测试游客、用量和错误审计记录；未操作注册用户账号，未新增、改动或删除正式文章及同步对象。保留这些记录便于核对真实调用成本；未声称已清理审计数据。
- 没有通过增加 CPU、修改 AI 并发或禁用安全保护来制造测试成绩。

## 资源与主要发现

首页 HTML gzip 后 303,081 字节；HTML 中引用的 24 个 JS/CSS 资源压缩后共 604,655 字节。每个冷启动代理下载合计 907,736 字节，约 0.91 MB。未下载图片、字体、动态 import 或 service worker 后续资源；未执行 JavaScript，未测 LCP、可交互时间、GPU 或手机掉帧。全部引用脚本下载完成也不等于首屏才开始显示。因此“两人同时下载超过 5 秒”不能表述为“两人在线网站就不能用”。

项目部署文档记录套餐为 4 核 / 4 GB / 40 GB SSD / 3 Mbps / 300 GB 月流量。CPU、内存和磁盘在服务器现场核对；带宽套餐没有登录腾讯云控制台复核。冷启动大资源传输与低带宽相符，带宽是优先排查方向，但此单点测试未隔离客户端网络、运营商路径、TCP 拥塞及服务端处理各自贡献，不能宣称已严格证明唯一瓶颈。

文章接口轮询公开推荐列表中的不同文章，读取真实正文 JSON，未读取登录账号数据。HTTP/1.1 的 64 并发两轮分别有 4/64、8/64 超过 3 秒；HTTP/2 有 14/64 超过 3 秒，全部返回有效文章与 HTTP 200。没有把 200 当作无卡顿。

AI 首段是服务器转发的完整结构化内容，不是保活字节。8 并发的流均正常结束。12 并发的四个拒绝返回“词典服务当前请求较多，请稍后重试。”，报告编号 `CR-20260922-A2E05C03`。这是当前应用的准入边界，不是上游模型服务的物理极限。

现场快照未显示内存耗尽或 CPU 持续饱和。结束时可用内存约 2.2 GiB；app 和 PostgreSQL 的 RestartCount 均为 0、OOMKilled 均为 false，所有正式服务健康，公开 connectivity 恢复正常且版本不变。未做连续高频资源采样，不能排除未捕捉到的瞬时尖峰。

07:06:40 UTC 起发现另一临时容器运行（非本测试创建）；因此之后的 HTTP/2 核对处在共享主机负载环境，不能认定完全隔离。此前 HTTP/1.1 的冷启动、40/64 文章边界复测和 AI 阶梯已完成，结果不依赖后续临时容器。没有干预该容器。

## 未验证与下一步

本轮没有验证登录后保存/同步写入、全文翻译与查词竞争、音频下载、真实浏览器完整用户旅程、多地域网络、持续数小时负载、数据规模增长或多日稳定性。此次结论是公开读取与真实词典的短时体验边界，不能作为全站最大并发或日活保证。各轮来自同一出口 IP；未出现 429，但更长压测需区分每 IP 120 请求/分钟保护与全站能力，不能为测试而关闭它。

优先优化首页 HTML/JS 传输体积，再评估静态资源分发/出口带宽；AI 优先考虑公平排队和查词/全文翻译资源分配。任何代码、并发或带宽修改后，用相同测试脚本复测，再增加混合真实用户场景。未在本轮实施优化。

## 复现与证据

脚本：`scripts/capacity-probe.mjs`、`scripts/summarize-capacity.mjs`。脚本硬性限制单轮并发 64，AI 单轮 12；每次命令只执行一档，不自动无限升压。一次请求 45 秒截止。不要对其他站点复用这些测试。
