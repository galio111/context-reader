## Jev：无须把网站部署到 Vercel

当前大陆服务器可以通过 AI Gateway API 调用 Jev。应用接口及 DeepSeek 回退已经存在。2026-09-20 已将私有 Gateway key 安装到当前生产运行环境，并经带认证的 Admin 接口确认两个 provider 已配置。大陆服务器模型列表请求成功（HTTP 200，包含 Jev）；未执行推理，新增测试费用为零。只重建 app/caddy，应用源码和 releaseId 仍为 `20260920T172600`，数据库等核心服务未重启。每日 ¥1、每月 Jev $4 及每日 150 次尝试上限保持不变。现在使用 `jev-shadow`；`jev-shadow` 是对照模式，会同时进行 DeepSeek 终审，**不会自动省掉 DeepSeek 费用**。只有用真实文章建立可信的误判对照后，才适合替代其中的判断。概率不是本项目上已经验证的准确率。

1. 登录 [Vercel AI Gateway](https://vercel.com/ai-gateway)，确认当前团队。
2. 进入 AI Gateway → API Keys → Create Key。名称可用 `context-reader-editorial`。若控制台提供 key 预算，设为每月 $4；关闭自动充值。
3. 查看当前团队能否访问 `typesafe-ai/jev`。若要求绑卡、购买额度或不在免费模型范围，先停在此处，继续使用 DeepSeek。不要为了完成配置默认充值。
4. 将密钥写入本机项目私有 `.env.local`：`AI_GATEWAY_API_KEY=...`。不要发到聊天，不要写入 `NEXT_PUBLIC_*`，不要提交 Git。
5. 可以先运行不调用模型的检查：`node --env-file=.env.local --import tsx scripts/check-jev-access.ts`。成功只证明模型列表可访问。
6. 经预算允许再做一次极小推理验证：同一命令末尾加 `--evaluate`。测试不触发 DeepSeek、不重试、不发布文章。今天没有执行这个步骤，因为尚无密钥且用户要求控制费用。
7. 告知代理“密钥已写好”后，代理检查私有配置，将该项安全加入当前大陆版本的 `.env.runtime`，按照版本化发布流程仅重建 app/caddy，核验 `/api/admin/editorial` 的 `jevConfigured`。不需要你手动改服务器或创建 Vercel 网站部署。
8. 后台切到“Jev 对照试用，DeepSeek 负责终审”。先少量对照，核查不完整正文、杂质、图注缺图等真实正反样本；验证前不承诺它能替代图片检查或所有分类。
