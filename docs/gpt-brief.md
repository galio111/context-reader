## 1. 项目与生产

Context Reader 是面向中文母语英语学习者的真实文章阅读工具。用户粘贴英文文章、导入公开 URL 或打开推荐/保存文章，在原文中点击单词、划选短语、查看中文语境解释，保存生词，并可使用全文翻译和 Anki。

- 正式地址：`https://context-reader.com`
- 正式主页：裸域名根路由；旧 `/home-v2` 只作为兼容入口跳回根首页
- 技术：Next.js 15、React 19、TypeScript、DeepSeek、本地优先浏览器数据、AnkiConnect
- 生产后端：腾讯云上海上的 PostgreSQL 17、GoTrue Auth、PostgREST、Storage 与内部兼容网关
- `context-reader-ten.vercel.app` 和原托管 Supabase 仅作回滚/参考

## 2. 产品目标与性格

阅读是主体验，查词、翻译、生词本、推荐、账号和 Anki 都是支持工具。成功不是“功能很多”，而是用户能在真实英文里更少中断地理解、积累和继续阅读。

阅读器应安静、清晰、适合长期使用；首页可以更有表现力，但必须快速进入真实阅读，不能变成通用 AI 官网、游戏、社交信息流或只在第一次惊艳的动效展示。

用户对质量要求很高：自己不满意就不会给别人使用。设计讨论不应急着实现；先同步视觉与功能意图，降低重构后的“开盲盒”和反复消耗。

## 3. 当前核心流程

1. 从粘贴、URL、推荐或已保存文章进入。
2. `ReaderView` 展示纯文本或结构化文章；URL 可保留标题、段落、列表、引用、有效图片和 `sup/sub`。
3. 点击单词或横向选择短语，流式解释直接长成最终面板。
4. 保存生词，保留音标、原句、上下文含义和 Anki 数据。
5. 在侧栏按需启动全文翻译；后台通常只建一条上游流连接，前台仍按文本 block 逐段出现并立即缓存。
6. 在阅读画布原位编辑文章，必要时删除整张图片 block。
7. 本地数据在登录后通过协议 2 同步到云端。

## 4. Reader 不可破坏边界

- 文章文字始终是视觉锚点。
- 编辑不能换成 textarea 或独立卡片编辑器；阅读/编辑必须共享字体、宽度、换行、行高和段落间距。
- 不要每次按键都用 React 受控 state 重画 `contentEditable`，否则光标会跳；历史按钮用隔离订阅更新，不能带动正文重渲染。
- 显式空段落是内容，必须保留；图片只读但可整块删除。删除图片/表格前后也要按可见块锚点恢复进度。
- undo/redo 是一次阅读会话的全局草稿历史，保存后仍可用，回主页后结束；左右箭头绝不写服务器，只有“保存编辑”提交一次。
- 手机竖向手势优先滚动；短语选择需要明显横向意图或长按。
- 原文章图片的图注沿用既有字号、颜色和间距，但与正文共享同一套词元选择、单词点击和短语语境查询；提取后只删除紧邻图片且与图注完全归一化相同的重复文本，不能删除不同正文；编辑模式仍禁用查词。
- 返回主页、切换文章和源句定位要正确重置或恢复滚动，不让旧状态吞掉新请求。

## 5. 查词、词典与全文翻译

- 文章查词只发送选中词/短语、当前句、前一句和后一句。
- 缓存未命中时先发起流式解释；流式结果完整即作为权威结果缓存，只有流式不完整才使用同一幂等 action id 请求结构化兜底。不得并行打两次 provider 请求，否则成功的流仍可能被另一条解析失败误记为错误。
- IPA 必须明确属于用户实际选择或输入的英文词形，并以 `phoneticFor` 校验；`原型` 与 `当前词音标` 分开显示，音频始终播放当前词。旧数据缺少归属且当前词与原型不同时隐藏 IPA，不能猜测补写。
- 独立词典支持中文词/短语、单个英文词或不超过 8 个词的英文短语；中英混输、过长输入和整句应在请求前说明不支持。
- 拼写错误只显示纠正，不得把正确词义挂在错误词头下，也不得进入历史或生词本。
- 圆形重新生成绕过缓存；若同词同原句已存生词，则更新生成字段但保留 id、创建时间和 Anki 记录。
- 全文翻译只能在侧栏内由用户启动。切换工具或短暂离开不能取消任务。
- 一次点击新任务只扣 1 次独立的月度全文翻译额度，上游流批次另行记录；重看完整缓存免费，明确重新生成再扣 1 次。打开侧栏与恢复部分缓存都不能自动扣量或启动模型。
- 普通文章把最多 80 个目标 block / 约 24,000 目标字符放进一条 DeepSeek 流；完整目标本身就是全文上下文，只序列化一次。只有缺段续传或超长后续批次才额外携带完整 `contextBlocks`，服务端上下文上限为 240 blocks / 64,000 字符，并按完整 JSON 对象边界转成 NDJSON 逐段转发，不依赖模型是否真的输出物理换行。若 Flash 把译文值放在与请求完全相同的 block 类型字段而不是 `translation`，只接受该 id 对应的精确类型字段，不能从其他字符串字段猜测。当前默认全文翻译模型为 `deepseek-v4-flash`，可用 `DEEPSEEK_TRANSLATION_MODEL` 覆盖。每完成一段仍立即保存，用户看到的逐段输出形式不变；零段失败必须明确说未生成，不得声称保留了段落。候选文章可在 Admin 直接录入现有整篇译文，生成或粘贴的完整译文会在点击精选时按正文哈希自动上传；用户首次点击仍扣 1 次，但模型调用与成本为 0。正文哈希变化后旧译文失效。
- 修改文章后只更新变化 block。强制重翻也不能先删旧译文；新段成功后逐一替换。

## 6. 首页：当前状态与已接受方向

### 当前已实现

`app/page.tsx` 服务端加载公开推荐摘要并交给 `HomeClient`；`HomeClient` 负责真实文章状态、预取、缓存和 `ReaderView`。大陆生产已经由根首页的 `HomeRedesign` 接管，并连接 SSR 外刊、导入、Menu、Reader 与来源会话栈；这只是评审基线，复杂动效仍未完成验收。

### 已接受方向与当前本地实施状态

以下列表同时包含已接入待验收、部分接入和仍待实现目标；必须以 `docs/home-redesign-implementation-audit.md` 的逐项状态为准，不能把整组误称为已完成。

- 保留现有封面和 Ballpit 球体碰撞效果，作为封面/品牌 IP。
- 舍弃全部封面翻页、内页翻页、滚轮翻页和自动收尾。
- 新用户/未登录用户顺序为“品牌封面 → 精选外刊（约 10 篇、约两屏；1 篇全宽主推 + 3 个完整三列标准行，可切换类型）→ 粘贴正文/输入网址 → 功能简介 → 联系/反馈”。数量允许围绕完整行小幅调整，不能留下单篇残行。精选外刊与自主导入是并重入口，语境解释/翻译仍是核心能力。
- 新打开站点时，登录用户进入快速路径。有记录时较小的继续阅读与更突出的导入器在同一工作台；最近文章列表不再重复，只保留“我的文章”入口。无记录时隐藏空继续阅读，导入器成为主景，外刊紧随。登录用户不重复功能介绍卡片。手机保持顺序，不要求都塞进同屏。
- 登录只更新身份与权限，不能抢走当前旅程。游客在首页或 Reader 中登录后保持原页面、文章、分类和滚动位置；下次重新打开网站才默认进入登录路径。退出登录后显示游客首页。当前账号页已有退出按钮，重设计必须保留。
- 登录用户每次全新打开或刷新网站时播放彩色粒子拼字加载动画；同一浏览中的内部返回和游客中途登录不播放。粒子从上方掉落，在中央清晰组成 `Context Reader`，只大写 C/R，保留正常单词间距。`FallingWordOpening` 已重采样清晰词形并在本地生产构建通过中段可读检查；手机、低动态和用户设备仍待验收。旧 Ballpit 螺旋卷入、球团与开孔登录动画已经舍弃。
- 新用户封面采用约 82–88vh 的完整品牌门面，底部露出精选外刊一线；静态结构是有留白的门面、无明显边框的中心球场、左侧克制文案，不是满幅球幕或常规左右分栏 Hero。第一屏主文案为“在语境里，读懂英文。”，并配一句克制说明和一个进入动作，但副文案、动作标签、行宽与断行均未定稿。封面背景仍待在纯净近白、极淡品牌色环境光、极淡图像三种可见方案中选择。
- 封面 Ballpit 略微透明；群体质心以很弱的力回到右侧宽活动区，单球保持随机热扰动、碰撞、鼠标响应和自由越界。向下滚轮与“精选外刊”按钮共用约 `1.9s` 的吸附时间线，向上倒放吸回封面；后续页面仍自然滚动。精选外刊同时从下方逐渐上移，列表完全就位的终点球体才消失。
- 推荐展示按用户提供的两段 Lusion 录屏高保真复现。桌面游客橱窗约 10 篇、约两屏，第一篇主推独占首行，之后严格每行 3 篇，不留单篇残行；默认分类是“推荐”，后面才是时事、科技、文化、商业等，各分类首页数量相近。分类切换是相同槽位的旧内容退场与新内容接续，不是瀑布流或追加。图片明显小于参考并使用 `4:3`，但局部 3D 与共享转场保持完整录屏强度。静止信息显示标题、来源、难度与阅读时长；色场自动提取封面低饱和主色；进入 Reader 后封面成为文章顶部持久内容，不自动淡出或卸载，只随正文自然滚出视口。手机主推全宽、其余两列且数量可减少，一次点按直接进入。
- Reader 不显示 `Context Reader` 品牌胶囊，左上按钮保持当前位置并始终写“返回首页”，但实际按来源快照恢复：外刊恢复分类/筛选/库存/滚动/卡片，继续阅读恢复工作台模块，我的文章与生词本恢复工作层/搜索/滚动/选中项；首页不重复最近文章列表。粘贴返回输入区但清空，URL 返回保留原网址但不恢复已删除的预览步骤。继续阅读和其他普通已保存文章入口恢复上次稳定正文锚点；未停稳的快速翻阅在退出时把下次入口重置到顶部，快速翻阅后稳定阅读 8 秒则恢复为正常阅读，正文底部稳定停留 8 秒视为读完并让下次从顶部开始。生词本原句跳转始终按目标词精确定位，不参与这套重置规则。Reader 内最多保留当前标签页 5 篇会话栈，浏览器后退与页面按钮同序。刷新直接回首页，已保存进度可继续。登录用户保留最近一篇未保存导入文章到本地临时槽位，下一篇替换，继续阅读标记“未保存”；游客不保留。主动退出登录结束 Reader 并去游客首页。
- 外刊卡片、转场层与 Reader 顶部封面表现为同一张图的连续共享对象，不同时绘制重复图片。点击立即并行请求正文，数据按时到达则只用 Lusion 转场完成进入，不显示通用加载动画；超时只在已落位封面下显示正文骨架。登录站点 Ballpit 开场与外刊进入互斥。游客反向约 `1.8–2.0s`，登录用户约 `0.9–1.2s`；非卡片来源使用 `180–260ms` 克制转场。
- 游客看到人工选择为主的首页外刊橱窗：桌面目标是一篇主推加三行三篇，手机目标是一篇主推加三行两篇。时事、科技、文化可由人工首槽设本栏主推；未设时按分类与图片状态自动排序。`推荐` 是 Admin 权威白名单，取消候选池后不得从全部精选库存补回；有偏好时只重排白名单内部文章。明确主推后面的三行绝不放无首页图片文章，图片不足时宁可少显示；无图文章只在展开区较后位置与有图文章穿插。登录用户点击“显示更多”后，剩余库存直接在当前首页下方延展，只提供分类和搜索。
- 点击推荐直接进入真实 `ReaderView`。
- 游客桌面首页的品牌胶囊悬停/聚焦后浮出输入文章、单独查词、生词本、我的文章四个按钮；登录桌面首页和 Reader 则固定显示四个按钮。首页直接打开的生词本与我的文章从按钮列右侧安全间距后开始，打开期间不显示按钮说明气泡；Reader 的独立面板保持自己的既有左侧定位，不复用首页偏移。首页单独查词复用完整 `BookDictionary` 单实例，桌面固定停靠在左侧并使用独立结果滚动，不再自由拖动、缩放或从浏览器存储恢复悬浮位置；手机从 Menu 打开底部停靠面板。鼠标彩色字母默认只在非 Reader 首页运行，可在 Menu 设置关闭。
- Reader 内导入新文章时保留旧阅读快照；新文章在当前 Reader 打开，明确返回动作恢复旧文章、滚动位置和解释面板状态，未提交编辑不得静默丢失。
- 日间和夜间是同等完整的产品状态。任何新增或重做 UI 都必须在同一轮定义两套配色，并覆盖默认、hover、focus、active/selected、disabled、loading、warning、error 和 placeholder；独立页面与 Menu 内嵌形态都要检查。普通文字和 placeholder 至少 4.5:1，大字与非文字控件至少 3:1，不能用 Tailwind 类名子串推断交互状态。
- Reader 长文始终使用真实块高度，不允许用 `content-visibility` 固定估算改变滚动条长度。未变更的文章从首次稳定渲染起一次构建并缓存完整逐词交互树，滚动期间不得再把纯文本与逐词 DOM 相互替换；阅读锚点测量在快速滚动时暂停，缺少固有尺寸的旧图片先用 4:3 占位，避免懒加载从零高度撑开页面。
- 桌面 Menu 位于右上，打开为紧凑浮层，不重复四个高频入口；未登录状态整行可直接打开登录。详情在同一浮层关系中替换或向左展开。桌面设置保留鼠标字母轨迹、日间/夜间和外刊图片 3D；手机设置只显示可点按的日间/夜间，偏好在浏览器持久化并作用于游客与登录路径。
- 账户详情先显示身份、登录与同步状态，再分组显示额度、数据导出和退出。阅读资料已接入：水平/兴趣可改，出生年份/性别可清除；手机号只读。用户自助修改昵称与六位密码仍未完成。注册基础账号后进入可跳过第二步，选填出生年份、性别、阅读偏好、英语水平；只有水平和兴趣参与推荐。
- 年龄只填出生年份；性别只选男/女；二者不参与推荐或公开展示。兴趣八类为科技科学、自然环境、文化历史、社会时事、商业经济、人物成长、故事文学、健康生活；水平为高中、四级、六级、考研、雅思/托福。生产生效仍需应用资料字段迁移并验证导出与清除。
- 外刊区已经接入个性化推荐控制，游客和登录用户均可修改，只影响默认推荐页，不取代内容分类。游客当前浏览器持久化，登录用户进入协议 2 跨设备同步；中途登录的当前页保持游客选择，账号云端选择作为下次默认。控件只承诺定期更新。

## 7. UI 与动效协作方式

用户可以只提供网址、5–15 秒录屏、截图或公开源码，不需要准确说出专业动效名称。实现前，Codex 应先复述：起点/终点、触发方式、位移/缩放/遮罩/层级/形变、节奏、技术不确定点和最小评审切片。

Lusion/共享图片首次评审必须把参考录屏和实现录屏并排，并列 `0/25/50/75/100%` 关键帧；达到参考后连续开合 5 次再讨论快速节奏。后半程已确认使用自然滚动、同一纸面缓慢换色和不同空间接力；手机缩短距离，低动态仅保留色场/布局接续。不能用全站统一淡入冒充完成。

注册现在只保留手机号标识、昵称与密码，不再出现资料第二步；账户已低调支持昵称与密码自助修改。当前手机号不发短信、也未验证归属，因此暂不开放密码找回；等合规短信验证上线后再实现自助重置。更新记录进入使用说明内容区，首页链接直达。

验收分三层，不能混为一谈：

1. 技术正确：构建、HTTP、回调、状态、控制台和响应式正常。
2. 视觉还原：在真实浏览器对比参考与实现的起点、25%、50%、75%、终点关键帧。
3. 产品体验：重复多次完成“主页→推荐→阅读→返回”，检查等待、滚轮冲突和认知负担。

浏览器/参考无法打开时必须标注“视觉未验证”；静态 bundle 推断不是亲眼观察。实现者自检不能替代用户的审美接受。复杂动效只有得到用户明确确认后才能被写成受保护行为。

问卷里的文字选项只代表结构假设，不代表用户喜欢或接受它暗示的 UI。视觉决定要提供可见草图或真实浏览器切片，并把“结构接受”和“视觉接受”分开记录。

- 当前公开测试注册：大陆手机号标识 + 昵称 + 6 位数字密码；不发短信，也不证明手机号所有权。内部 synthetic email 不能显示。

- 本地修改约 800ms 后进入按对象类型收窄的上传队列，并等待滚动/输入安静两秒及浏览器空闲窗口再处理重数据。可见页约 15 秒只做增量 pull，并在 focus/visibility 返回时检查；无变化时不读取、哈希、压缩或重写文章/生词/缓存，也不广播无效合并事件。阅读打开时间与滚动锚点使用独立 `reading_state`，不能再为了保存进度重写整份文章库。手动同步和登录/退出前同步仍做完整 reconciliation；不能恢复成每次下载完整历史。
- 离线模式只开放上次验证账号在当前浏览器的文章、生词、阅读状态和缓存，始终明确提示；不恢复 Admin、套餐、额度或 API 权限。

## 11. OCR、错误与安全

- OCR 不是当前用户功能。当前页面、帮助、Menu、额度和离线文案都不提供 OCR 入口或承诺。
- OCR provider、路由和旧 metadata 为兼容保留；`ArticleInput` 和 `ReaderView` gate 关闭，URL 图片不自动 OCR。
- 用户错误要区分输入不支持、断网、账号/额度和站点/上游故障；不能显示 `Failed to fetch`。
- 站点/上游/配置/客户端处理错误使用可追踪 id，先写私有存储，再可选发邮件；断网和输入错误不存为 bug。
- 所有 API 维持请求体上限、成本限流、并发闸门、同源 Admin 写入、DNS pin、私网阻断和通用外部错误。浏览器没有 Supabase key，RLS/权限撤销必须真实执行。

## 12. 模型与重要路由

DeepSeek 路由关闭 thinking。文章划词释义/句子翻译与单独查词由 `DEEPSEEK_LOOKUP_MODEL` 控制并默认 `deepseek-v4-flash`；全文翻译的专用覆盖是 `DEEPSEEK_TRANSLATION_MODEL`，默认同样为 Flash。`DEEPSEEK_MODEL` 继续覆盖摘要等其他 DeepSeek 功能，`DEEPSEEK_FALLBACK_*` 保留显式回退能力。Admin “每日运行情况”读取最近 30 个上海自然日的完整执行账本并逐日展示用量、输入/输出 token、成本估计和失败执行；另按功能汇总并单列全文翻译。可见成本使用 DeepSeek 直接人民币价逐条重算，2026-08-23 起周末全天低谷、工作日 9–12 点和 14–18 点高峰；超过 50,000 条时明确提示统计上限，实际扣费始终以 DeepSeek 控制台为准。

关键路由：

- `/api/explain-word*`：文章语境解释
- `/api/dictionary*`：独立双向词典
- `/api/translate-article`：全文翻译
- `/api/import-url`：正文优先的安全 URL 导入；Reader 先打开，图片后台转为第一方，单图失败只移除图片
- `/api/pronunciation`：统一云端发音
- `/api/public-articles*`：公开推荐
- `/api/auth/*`、`/api/account/*`、`/api/usage/*`：账号、同步、用量
