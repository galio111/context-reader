# Substack extraction and a16z source

Status: implementation and local regression verified; production acceptance and persisted source activation pending.

The reported public import reproduced on accepted release `20261006T000033`: the a16z Top 100 Consumer AI Apps article returned HTTP 200 with 97 text characters, one metadata-cover image and discussion/footer labels. Its fetched initial HTML already contained the full body. The shared noise regex treated the `newsletter` token in the article's `newsletter-post` class as a signup widget and removed the entire ancestor before Readability ran. This incident was an extraction defect, not evidence of a required JavaScript browser or a blocked network response.

The defect affects a shared template. Six a16z articles and two One Useful Thing articles reproduced before the fix (95–210 text characters). All eight now retain the inspected substantive paragraphs in order, images and publication dates. A non-Substack Paul Graham control remains byte-identical at the text level. These samples establish cross-site impact, not an exhaustive census of publishers. Other known semantic collisions already handled in this repository include Popsci's public `paywall` body, Mongabay's `byline-*` article taxonomy and Reasons to be Cheerful's `social-side-wrap` body; broad class-name deletion must always be checked against actual publisher structure.

The shared Substack profile recognizes the combination of an article wrapper and publicly delivered `.available-content .body.markup`; it removes only the misleading `newsletter-post` token and marks the body boundary. It never removes hidden/paywall restrictions. A recognized Substack post with no usable body fails rather than returning comments or footer text. Signup/embedded story controls are excluded, while figures use the existing bounded media path. a16z's final boilerplate requires its exact opening plus both disclosure links before removal. Original substantive conclusions and non-terminal quotations remain.

Publication metadata is captured before script cleanup so JSON-LD dates survive. The reported article now has 2,949 English-word tokens, 82 blocks, all five numbered sections, 22 substantive images and publication time `2026-10-05T14:01:42+00:00`. Counts use the crawler's letter-token regex and exclude a16z's terminal newsletter disclaimer.

a16z's public RSS currently delivers 20 items, including 1, 2 and 5 October entries; robots allows the public feed and article paths. The source is business/technology, advanced, daily target two under the existing shared scheduler. Default source registration remains disabled until production verification. Admin activation must retain the server-owned verification result. Substack's feed has no verified WordPress pagination; after two empty batches it yields until a later run rather than requesting the same feed as six archive pages.

Automatic selection still requires more than 400 words, images, complete ordered extraction, current publication evidence, full content/image audit, suitable difficulty, deduplication and the shared budget. Investment announcements or promotional posts may be rejected. The reported Top 100 article is available for manual reading but existing list/title and image-count gates exclude it from automatic selection. Enabling a source does not promise a daily quota of accepted articles.

Runtime robots rules are refreshed every five minutes. RSS discovery reads current items each run and deduplicates already handled URLs/titles/bodies; it is not a fixed article list. Extraction rules remain versioned, evidence-backed code with positive and negative regressions. Arbitrary website instructions or model suggestions cannot rewrite the sanitizer at runtime. The new fail-closed behavior turns detected Substack layout loss into a visible failure and crawler issue; unobserved future templates still require diagnosis and review.

Local checks: 90 critical regressions; 29 extraction/discovery/media checks; 49 editorial/provider/fetch checks; 12 source-priority/Substack checks; nine protected release contracts. Eight live publisher pages were compared against their raw HTML, and a synthetic two-snapshot RSS regression proves new-item discovery and duplicate exclusion. This test simulates a future feed update; it does not claim a future scheduled run was already observed.
