## 模块责任

| 模块 | 最终责任 | 保留的外部契约 |
| --- | --- | --- |
| `lib/readerDocumentModel.ts` | 从已有正文块编译渲染模型及词、段落、句子、词源索引；缓存仅保留当前文档使用的条目 | 原有 token id、上下文、表格/图片说明/空段落/行内格式、远块交互窗口；Reader JSX 与 CSS 沿用原实现 |
| `lib/translationCacheRepository.ts` | 按指定全文或段落记录读写，兼容普通 Storage，封装持久化边界 | 原有缓存 key、字段、同步通知、迁移和失败不清空结果 |
| `lib/learningStorage.ts` | 用单个批量 delta 更新所需记录，沿用 IndexedDB 事务及跨标签页机制 | 不变更数据库版本和现有 collection 格式，不序列化无关翻译历史 |
| 翻译 transport / progress / job 模块 | 分开处理请求流、续传与重试、进度聚合、任务归属与取消 | 显式启动、后台继续、完整上下文、逐块显示、一次操作计费、强制重生成保留旧结果 |
| `components/useReaderTranslationSession.ts` | Reader 保持挂载时，按已验证账户和准备完成的存储 owner 绑定缓存及任务 | 登录后能显示进度/结果，切账户不保留旧译文；同账户编辑保留待更新译文 |
| `lib/accountStorageTransition.ts` | 无依赖的临时生命周期信号；覆盖账户归档、恢复及退出的异步等待 | 不新增持久化字段、不提前改 owner；过渡中旧任务不能写入、新任务不能启动 |
| `lib/vocabularyRepository.ts` | 解码、归一化、去重迁移和单个 Storage 的私有快照缓存 | `vocabulary.ts` 导出 API 不变；key、id、创建时间、词源、Anki 信息、备份、删除 tombstone 保持 |
| `lib/vocabulary.ts` | 新增、更新、重新生成、标记导入、删除等领域操作 | 调用方每次得到独立对象，修改返回结果不会污染缓存或其他读取 |
| `lib/requestSecurity.ts` 静态资源策略 | 严格有效的构建 JS/CSS GET/HEAD 使用独立读取限流，避免页面资源耗尽业务额度 | 静态读取仍有 600/min 上限；普通 API、AI、账号/Admin、请求大小与来源保护保持 |

生词本快照同时检查 Storage 实例、账户 owner、原始存储字节。同步直接覆盖、切换账户、删除、损坏后恢复都会失效；迁移通知同步重入时，只有数据仍匹配才建立快照。规范化记录只有 `anki` 与 `sourceArticle` 是嵌套对象，均单独复制。

独立连续冷启动暴露既有静态资源限流问题：真实 HTTP 直接请求压缩 CSS，第 121 次返回 `429 site_rate_limit` JSON，浏览器因此报告样式 MIME 错误。修复把静态读取从业务 `api-all` 桶分离，仅允许安全路径；同一 IP 读取资源后，AI/Auth/Admin 仍保留原有限额。原始失败与定位证据保留在独立审核，不能将它归为随机浏览器异常或通过忽略错误验收。

## 测量口径

本机固定数据集上的 CPU 测量不包含公网传输、模型生成、真实手机和整页首屏时间，不能换算为网站整体提速百分比。新增脚本允许重跑，机器负载会影响绝对耗时。

| 场景 | 基线 | 候选 | 依据 |
| --- | ---: | ---: | --- |
| 1,500 条生词反复读取，中位数 | 23.722 ms | 0.275 ms | 原生产 `vocabulary.ts` 与候选各预热后运行 60 次，记录数量相同 |
| 同场景 P95 | 28.854 ms | 0.610 ms | `scripts/benchmark-vocabulary-repository.ts` |
| 1,200 段正文冷构建 | 83.159 ms | 41.179 ms | 独立审核重新运行原版与候选 |
| 1,200 段已有缓存刷新 | 80.184 ms | 17.802 ms | 原有模型字段逐项相等 |
| 5,001 条译文历史中读取 50 个段落 | 114.019 ms | 0.062 ms | IndexedDB 记录级读取 |
| 同历史中更新一个段落 | 17.049 ms | 0.010 ms | 只更新指定记录 |

独立审核另测生词本中位数 17.35 → 0.2405 ms，与实现侧改善方向一致。UI 对比独立于构建及单元测试；物理设备、其他浏览器、词典发音实际听感与用户最终观感不能由本机 Chromium 自动化代替。

## 后续修改的约束

用户补充的首要目标是减少“改这里、坏那里”。本轮把依赖方向与行为测试一起作为维护入口：document model 和 progress 是纯数据层，transport 只处理请求协议，repository 只管理存储，job 编排生命周期，React hook 绑定已就绪的账户会话。纯数据层不能反向调用 UI，传输不能直接写缓存；依赖边界和循环检查在测试中执行。扩展依赖必须同时修改责任说明与相关行为回归，不能仅放宽导入白名单。

保留原有 facade 的调用接口和所有持久化格式，调用方不需要理解 IndexedDB 行级操作或生词迁移。针对高风险协作点，固定测试旧流迟到、强制重生成、启动中取消、账户切换、登录时 Reader 不卸载、后台继续、旧记录迁移及编辑后撤销。测试与功能契约用于缩小改动影响并尽早暴露回归，不代表未来修改绝不会出错。

日常修改先运行 `npm run test:architecture`；发布还要运行核心、供应商回退计费、契约检查、出口审计与生产构建。`.github/workflows/architecture-regressions.yml` 在 `main`、`codex/**` 推送与 pull request 时自动执行这些检查。工作流仅有仓库读取权限，不使用生产凭据，不执行部署。GitHub 检查状态与本地通过应分别记录；是否设置为受保护分支的必需检查属于仓库配置，本次不声称已经开启。
