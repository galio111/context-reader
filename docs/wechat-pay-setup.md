# 微信支付开通与上线指南

核对日期：2026-10-02。当前实现为普通商户 API v3 Native 扫码支付；月付、年付都是一次购买，不签自动续费协议。支付未配置时页面可查看价格但不会创建可付款订单。真实收款必须等主体、权限、密钥及小额实付/退款验收完成。

## 你先做什么

1. **先核实已有备案。** 当前生产页页脚已显示“蜀ICP备2026045148号-1”和“川公网安备 51010702044616号”。这只能证明网站展示了编号，不能代替官方查询。请在[工信部备案系统](https://beian.miit.gov.cn/)核实 context-reader.com、备案主体和接入商是否对应。若已有备案，不要重复申请；若只是旧信息或主体将变化，应走接入商的备案/变更流程。
2. **确定收款经营主体。** 普通商户入驻需要实际主体资料、经营者/法人身份证明、结算账户与联系人资料。个体工商户和公司能申请的产品范围不同，不要把“个人收款码”当成网站商户 API。本次接的是普通商户，不是服务商替子商户收款。官方资料清单见[入驻填写指引](https://pay.wechatpay.cn/static/applyment_guide/applyment_detail_app.shtml)；以对应主体、真实经营类目的提交页面为准。
3. **先确认业务资质，再决定是否注册个体或公司。** 说明业务为英语阅读辅助工具，收费对象是查词/翻译等软件服务，提供真实网站和套餐页面。收费软件是否落入需要增值电信业务许可的范围，不能只凭“收了钱”或“已有备案”判断，应向属地通信管理局、接入商及微信商户审核咨询具体业务。官方制度区分非经营性备案与经营性许可：[通信管理局服务指南](https://hunca.miit.gov.cn/bsfw/bszn/art/2024/art_7ef0d8bd3b0d433ba4b9b277f883f74d.html)。
4. **申请微信支付商户号。** 在[微信支付商户平台](https://pay.weixin.qq.com/)提交真实材料，网站收款场景选 PC 网站，完成账户验证、审核与协议签署。申请、实名验证和签约需要你本人/经营主体管理员完成。不要提交伪造或借用的资料。[官方 Native 接入步骤](https://pay.wechatpay.cn/guide/qrcode_payment.shtml)
5. **准备并绑定 AppID。** 按商户平台要求注册、认证受支持的公众平台账号，并完成商户号与 AppID 的双向绑定。商户号 mchid 和 AppID 是两种不同编号；有商户号不代表已经绑定、有支付权限。
6. **开通 Native 支付权限。** 商户平台产品中心核对 Native 是否已经可用。本版流程是网页生成订单二维码，用户用微信扫一扫支付。[Native 下单接口](https://pay.wechatpay.cn/doc/v3/merchant/4012791877)

## 手机付款要另外注意

Native 是扫码流程，在同一部手机浏览器里付款并不如直接调起微信方便。本版手机页面会说明可在电脑上打开扫码，不会伪造 H5 支付按钮。

若你希望手机浏览器直接唤起微信，需要另外申请 **H5 支付**，不是 Native 开通后天然附带。本次没有实现或宣称 H5/JSAPI 已可用。按目前官方开发准备文档，H5 可申请主体列出企业、事业单位、政府机关、社会组织，不能先假设个体工商户一定有此权限。应在选主体时就咨询确认。[H5 开发接入准备](https://pay.wechatpay.cn/doc/v3/merchant/4015614193)

H5 域名要在商户平台审核。当前官方配置页对经营性网站提出 ICP 许可证要求，并要求备案主体关系证明；域名与商户主体不一致不是随意加一份说明即可，允许的授权关系及材料受限。不要依据旧教程承诺“个人备案加个收款码就能接”。[H5 域名要求](https://pay.wechatpay.cn/doc/v3/merchant/4013287193)

微信内置浏览器中的 JSAPI 支付是另一个流程，还涉及 openid、网页授权/支付目录及相应 AppID 权限，后续单独接入。

## 审核后交给部署人员的参数

这些参数通过服务器私密配置安装，不发到聊天记录、不放 Git、不放前端环境变量。

| 环境变量 | 内容 |
|---|---|
| WECHAT_PAY_ENABLED | 先 false；全部验收后设 true |
| WECHAT_PAY_APP_ID | 已与商户号绑定的 AppID |
| WECHAT_PAY_MCH_ID | 普通商户号 |
| WECHAT_PAY_SERIAL | 商户 API 证书序列号 |
| WECHAT_PAY_PRIVATE_KEY | 商户 API 私钥 PEM；支持转义换行 |
| WECHAT_PAY_PUBLIC_KEY_ID | 微信支付公钥 ID，以平台实际值为准 |
| WECHAT_PAY_PUBLIC_KEY | 对应的微信支付公钥 PEM |
| WECHAT_PAY_API_V3_KEY | 商户平台设置的 32 字节 API v3 密钥 |
| WECHAT_PAY_NOTIFY_URL | https://context-reader.com/api/billing/wechat/notify |

不要混淆商户私钥与微信公钥，也不要将 AppSecret 当 API v3 密钥。本版采用微信支付公钥验签方式；若商户配置为平台证书模式，应先切换匹配的密钥模式或补充对应证书轮换适配，不能跳过验签。[官方公钥验签说明](https://pay.wechatpay.cn/doc/v3/merchant/4013053249)

部署配置位于服务器受限的 .env.runtime，Compose 的 app 服务读取它；安装后仅按版本化流程重建 app/caddy。平台公钥更新时同步更新公钥 ID/内容并验证，不能简单接受任意回调公钥编号。

## 本版接口与防重逻辑

- GET /api/billing：公开套餐、点数、月价年价、支付开放状态。
- GET /api/billing?account=1：登录账号自己的会员和最近订单。
- POST /api/billing：quote 报价、create 下单、check 查询；必须登录且同源，报价由服务端生成。
- POST /api/billing/wechat/notify：验签、API v3 AES-GCM 解密，再核对 AppID、商户号、币种、订单号与金额。
- GET/POST /api/admin/billing：管理配置、查看最近订单及异常未履约订单原路退款。
- 微信支付成功页/扫码后的前端状态不能发会员。签名正确的通知或签名正确的主动查询，经数据库原子结算才发放；重复通知不会重复发放。
- 抵扣期间若权益依据变化，已付金额记为待处理异常订单，不发放重复权益；管理员执行原路退款，到账以微信查询状态为准。
- 正常已履约订单的售后退款目前需人工核对使用情况和权益撤销，再在商户平台处理。本版不提供自动按比例售后退款；后台“原路退款”仅限从未发放权益的异常订单。不能直接把 paid 改 refunded 而保留权益。
- 账单对账和退款结果需运营人员定期在商户平台核对；本版没有日结自动对账任务。

## 开放收款前的最后验收

在自己的真实商户号配置完成后，先进行受控的小额真实购买；正式价格仍由后台管理，测试结束恢复。真实付款由你完成。

逐项核对：首次月付、年付每月发放、续购重开周期、剩余权益抵扣、年付补充点数、重复通知、返回页面主动查询、支付过程中额度变化、超时订单、异常订单退款，以及跨账号无法读取订单。验证微信账单金额、后台订单、用户权益与点数一致后再公开开放。

还应补全与实际经营主体一致的联系信息、用户协议、隐私政策、退款说明和发票/售后处理方式；这些商业条款由你确认。不能仅凭接口代码通过测试就称微信支付已开通。

费用以申请页面/合同为准：商户入驻通常不收申请费，交易服务费按类目与合同；公众账号认证、主体注册和可能的资质办理是另外的成本，不应把这些当成每笔 API 调用费用。[官方入驻费用说明](https://pay.wechatpay.cn/static/applyment_guide/applyment_detail_app.shtml)
