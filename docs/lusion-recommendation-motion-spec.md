# 精选外刊 Lusion 动效复刻规范

这份文档把用户于 2026-08-12 提供的两段 Lusion 录屏转成可实现、可逐帧验收的动效规格。它只定义精选外刊展示与进入阅读的交互语言，不授权复制 Lusion 的品牌、文案、项目内容或私有源代码。

## 1. 状态与证据

**当前状态：视觉参考已确认，尚未实现。**

- 录屏一：`屏幕录制 2026-08-12 171544.mp4`，1918 × 1034，约 9.62 秒，30 fps。覆盖项目网格悬停、连续滚动、反向滚动和下一段场景露出。
- 录屏二：`屏幕录制 2026-08-12 171742.mp4`，1918 × 1030，约 7.74 秒，30 fps。覆盖卡片悬停、点击、共享图像放大转场、色场承接和详情内容进入。
- 本次结论来自实际录屏关键帧，不再属于“只看压缩 bundle 的视觉推断”。
- 录屏能确定视觉输出、触发方式、层级和大致时间关系，不能证明 Lusion 私有 shader 公式、弹簧参数或组件源码。Context Reader 的目标是画面与手感高保真等价，不是复制私有实现。

复刻时不得把“构建成功”“页面能打开”或“技术路线相似”当成视觉已经达标。最终仍以同尺寸录屏逐帧叠加比较和用户确认作为准入门槛。

## 2. 录屏一：静止网格与悬停

### 静止状态

- 参考录屏本身使用自然纵向文档流和双列编辑式网格；Context Reader 只复刻其动效语言，当前产品映射已改为三列索引与较大主推。
- 图片是圆角横向画幅，标题与简短元数据位于图片下方，不压在图片内部。
- 图片 DOM 边框在悬停期间保持稳定；动的是边框内部的图像表面，而不是整张卡片做普通 `scale()`。
- 当前悬停项目的标题旁出现方向箭头，箭头会随悬停目标切换。

### 指针进入后的连续变化

1. 指针坐标被映射为图片内部的局部作用点。
2. 图像在作用点附近产生有景深感的位移、拉伸与清晰度变化，远端区域以较弱幅度响应。
3. 图像像一张有厚度、带弹性的表面跟随指针，而不是一层均匀模糊滤镜。
4. 指针移动后效果存在短暂惯性和回弹，不直接吸附到新坐标。
5. 指针离开后，形变与焦点平滑归零，标题箭头同步退出。

从录屏可观察到，Of The Oak 与 Oryzo AI 的悬停响应都会随指针位置改变形变中心；同一张图在连续半秒内的锐度、局部位移和透视并不相同。因此以下替代实现不合格：整图缩放、单一 CSS `blur()`、固定径向遮罩、只有亮度变化或一次性 hover 动画。

## 3. 录屏一：滚动时的图像出现方式

### 已观察行为

- 滚轮仍然执行正常页面滚动，没有分页、吸附或滚轮语义劫持。
- 卡片随文档自然进入视口，但图片内容相对其 DOM 边框出现纵向滞后、轻微倾斜、拉伸和速度相关的模糊。
- 快速滚动时形变更明显；速度降低后图像回到静止构图。
- 反向滚动会产生相反方向的滞后，说明效果更接近连续滚动速度驱动，而不是只播放一次的进入动画。
- 标题与元数据在高速滚动中可见裁切/位移式过渡；它与图像形变的节奏一致，但仅凭录屏不能断言文字也由同一 shader 渲染。
- 固定导航在滚动和转场中保持稳定，形成场景的空间锚点。

### 复刻要求

- 使用真实 `scrollY` 与平滑后的 `scrollVelocity` 驱动形变强度和方向。
- 图片网格的 DOM 布局保持可访问、可响应和可自然滚动；WebGL 图像层必须持续同步每个可见图片的 `getBoundingClientRect()`。
- 新卡片出现不能退化为普通 `opacity + translateY`。核心是“图片表面与页面滚动不同步一瞬，再弹回”的空间感。
- 页面停止后必须完全稳定，不能留下模糊、漂移或一像素持续抖动。

## 4. 录屏二：点击后的共享图像转场

录屏二不是“淡出列表，再打开新页”。被点击的图片从原卡片位置成为跨场景的同一个视觉对象。

### 五个关键阶段

1. **起点：** 卡片仍在网格中，悬停形变和标题箭头处于可见状态。
2. **抬升：** 周围网格、标题和非选中内容先向浅色/透明退场；选中图片脱离原层级，从精确的卡片边界开始放大。
3. **占场：** 图片在放大时发生明显的三维倾斜、透视、局部拉伸和动态模糊，越过视口边缘；相邻卡片短暂留下边缘残影，强化前后层关系。
4. **色场承接：** 图片纹理被压缩、模糊或溶解成与内容关联的纯色背景；固定导航继续存在，中间有一个故意留白的呼吸段。
5. **目标显现：** 新场景的标题、说明、操作与媒体区域分层进入；媒体区域先出现容器，再逐渐显示真实内容。

按录屏时间轴粗略观察，点击后的图像占场主要发生在约 0.5 秒内，色场承接与留白约持续 0.8–1.0 秒，目标布局在约 1.8–2.0 秒附近进入稳定状态。最终参数不能只照抄这些估算，必须用实现录屏与原录屏对齐后校准。

### 不合格的近似实现

- 点击后直接路由切换并从白屏淡入；
- 复制一张 `<img>` 只做均匀 `scale()`；
- 先隐藏原卡片，导致起点跳一帧；
- 放大过程中没有透视、纹理形变和速度模糊；
- 列表与目标场景之间出现白闪、图片重载或导航跳位；
- 为了实现转场而增加一个与阅读无关的文章详情中间页。

## 5. 映射到 Context Reader

### 从 Ballpit 封面进入列表的连续交接

这段交接是 Context Reader 自己的品牌转场，不是 Lusion 录屏已经提供的效果。2026-08-12 的最新确认把它约束为一条连续时间轴：

- 封面等待用户时，球体持续自由漂移、互相碰撞，不提前停稳，也不在后台换成适合开孔的预设位置。
- 用户第一次向下自然滚动或点击主操作时，直接采样这一帧中每颗球的位置和速度；同一画布中的开孔力场从这些实时状态开始施力，并以向左右两侧让出通道为主要方向。第一次向下意图启动自动播放，不需要持续滚动控制进度；点击使用同一时间轴。严禁重建 Ballpit、重播初始种子、把球瞬移到两侧或先切换到另一幅画面。
- 精选外刊真实 DOM 从视口下方逐渐上移。它不是先隐藏再突然显示；图片在上移期间同时出现与 Lusion 录屏一致的速度相关滞后、拉伸、轻微倾斜和回弹，停止后恢复稳定构图。
- 球体散开与列表上移大部分时间重叠。列表未到最终位置前，球体仍然可见；列表完全就位的同一终点，球体才完成退场，随后才允许卸载封面 WebGL 资源。
- 自动时间轴的首轮目标时长为约 `1.4–1.8s`。播放尚未完成时，明确的向上滚动从当前进度自然反向；到达完整外刊视图后不因轻微回滚重播开场。滚轮监听不得恢复翻页格数或多页面状态机，也不得让浏览器长期失去自然滚动所有权。
- 精选外刊游客橱窗桌面约 10 篇、约占两屏自然滚动内容。第一篇主推独占第一行全宽，下一行开始每行 3 篇；标准三列网格不允许出现只显示一篇的残行，精确总量可按满行规则在约 10 篇附近调整。图片使用 `4:3` 常规文章封面比例并保留页面侧边留白，不使用细长横幅。外刊类型切换位于标题下方，默认先显示“推荐”，其后才是时事、科技、文化、商业等横向文字分类。各分类首页数量大致相同；切换时保持网格槽位和页面高度稳定，旧内容从原位置退去，新内容在相同位置接续并带轻量速度形变，不做瀑布流重排或向当前列表追加。
- 图片明显缩小与完整复刻动效并不冲突。局部形变使用图片自身 UV、归一化指针坐标和相对尺寸驱动，保持录屏中的透视、景深、惯性和回弹强度；共享图片点击转场也从较小 DOM 边界连续放大到占场。缩小可能降低静止帧里局部纹理细节的可见度，但不得被解释为形变或共享转场只能变弱。

低动态模式保留“球体让出内容、列表进入”的空间因果，但改成短距离移动和清晰交叉淡化，不运行持续形变。WebGL 失败时直接显示可读列表，不得阻塞进入文章。

### 保留的 Lusion 动效语法

- 三列编辑式文章陈列与一篇较大主推；
- 指针驱动的局部三维图片表面；
- 原生滚动中的速度形变和回弹；
- 点击后从原图片边界开始的共享图像占场；
- 图像溶解为色场，再分层显现目标内容；
- 动效期间有稳定的全局导航锚点。

### Context Reader 自己的内容与产品边界

- 板块名称优先使用“精选外刊”，让用户立即联想到真实英文刊物和阅读难度。
- 卡片展示来源刊物、标题、简短摘要或主题、阅读时长/难度等真正有助于选择文章的信息，不复制 Lusion 的项目服务标签。
- 图片明显小于参考网站，以一屏看见更多真实文章为目标；具体宽高在浏览器中与用户共同确认，不把暂定面积数字写成永久设计令牌，也不因尺寸缩小主动降低 shader 强度。
- 视觉秩序吸收 I Read World 的简洁和清晰：静止时文章信息必须一眼读懂，动效不负责弥补混乱的信息架构。
- 保留 Context Reader 的 Ballpit 封面和鼠标字母作为品牌入口，但精选外刊进入后不继续堆叠球体、字母和图像 shader，避免多个强动效争夺注意力。
- 滚轮永远只做自然页面滚动，不恢复任何翻页、吸附或章节切换语义。

### 点击文章后的正确终点

点击必须连接现有真实 `ReaderView`，不是仿造 Lusion 的项目详情页。共享图片仍完整经历“原位抬升 → 占场 → 色场承接 → 落入文章顶部 → 内容显现”。色场从对应封面自动提取低饱和主色，并对不适合的取色设置品牌回退；落地后的封面是文章顶部真实、持久的图片内容，不自动淡出、缩走或卸载。读者向下阅读时它随正文自然离开视口，回到文章顶部仍然存在。查词、全文翻译、生词本、保存、缓存、账号与同步继续使用现有实现。

Reader 复用当前左上返回首页按钮的现有视觉与位置，不增加另一套返回控件；动作语义改为回到打开文章时的来源界面，恢复进入前分类、文章顺序、滚动位置、原卡片与“显示更多”展开状态。游客返回首版播放完整反向共享图像转场，让顶部封面回到原卡片；登录用户首版提供缩短的反向共享版本，以减少重复等待。压缩版的持续时间和关键帧删减必须与完整版本在真实浏览器中对比后确认，不能直接退化成淡出或瞬切。

为了同时尊重“完整复刻”与“快速进入阅读”，第一轮应先按录屏节奏做完整版本供用户验收，不擅自把转场缩短成普通淡入。只有在视觉达标后，再通过连续多次“推荐 → 阅读 → 返回”测试判断是否需要为重复使用提供更快节奏。产品体验调整不能冒充视觉复刻。

`ReaderView` 仍然以安静、白色、正文优先为终态。过渡色可以从封面预先提取的低饱和主色生成，但必须在正文出现前干净退场，不能把 WebGL 形变带进实际阅读滚动。

## 6. 推荐实现架构

这不是源代码结论，而是最有可能达到录屏效果且适合当前项目的实现路线：

- 服务端继续由 `app/home-v2/page.tsx` 输出真实公开推荐，语义、链接、图片替代文本和首屏内容保留为普通 DOM。
- `HomeClient` 继续掌握真实推荐预取和进入 `ReaderView` 的回调；转场层只编排时机，不复制文章状态机。
- 页面使用一个共享 Three.js/WebGL 渲染器，而不是每张卡片各建一个 canvas。
- 每张可见图片对应一块与 DOM 矩形同步的 mesh；只为视口及邻近区域加载/更新纹理。
- 自定义 vertex/fragment shader 至少接收局部指针、hover 进度、滚动速度、点击进度、源/目标矩形、宽高比和纹理等 uniforms。
- 使用 requestAnimationFrame 下的阻尼/弹簧值平滑指针、滚动速度和形变进度；DOM 标题使用独立 overflow mask 与 transform，避免把可访问文字画进 canvas。
- 点击时把当前 mesh 提升到固定转场层，锁定其最后一个源矩形，在转场完成前不卸载列表；Reader 数据和目标图片应提前可用，避免中途白闪。
- 限制设备像素比和纹理尺寸，暂停离屏 mesh，避免每帧布局抖动；桌面目标是稳定 60 fps，低性能设备优先保证输入和滚动响应。

公开 bundle 曾提供 Three.js/WebGL、DOM/mesh 同步和后处理方向的旁证，但不会被当作可复制的私有源代码。最终 shader 仍要根据这两段录屏从零调校。

## 7. 手机、键盘与低动态模式

- 手机没有 hover，正常纵向滚动仍是最高优先级；滚动形变应显著减弱，不能影响触控跟手或文字稳定。
- 轻点文章使用同一共享图像身份，但可以减少大角度倾斜，避免小屏裁切成无意义色块。
- 键盘聚焦卡片时提供稳定的标题箭头、轮廓和轻量景深状态；按 Enter 进入真实 Reader。
- `prefers-reduced-motion` 下取消 shader 形变、速度模糊、旋转和长留白，改为短共享图片/淡入过渡；功能和空间关系仍要清楚。
- WebGL 初始化失败时退化为静态图片与直接阅读，不阻塞文章入口。

## 8. 首个可评审切片

不先制作一个脱离功能的整页视觉稿。首个切片直接位于真实 `/home-v2`，使用一行或两行真实 SSR 文章，同时完成：

1. 更小的三列文章构图、较大主推和静止信息层级；
2. 一套共享 WebGL 图像层；
3. 卡片悬停与滚动速度形变；
4. 至少一张真实文章的完整点击转场；
5. 转场结束后进入真实 `ReaderView`；
6. 返回推荐区后恢复原滚动位置和稳定图像状态。

这一切片足以同时检验画面、性能、进入阅读速度和功能接线。用户确认前，不扩展到整站、不删除旧引擎，也不把未通过的动效写成受保护行为。

## 9. 视觉验收清单

### 悬停

- 参考与实现使用相同视口和相近图片构图；
- 对比进入、25%、50%、75%、稳定和离开帧；
- DOM 圆角边界稳定，形变中心随指针移动；
- 局部景深、透视、惯性和回弹均可见；
- 标题箭头与当前悬停卡片一致。

### 滚动

- 慢速、快速、急停和反向滚动各录一次；
- 滚轮只滚页面；速度越大形变越明显；
- 图片矩形与 DOM 不脱轨，停止后完全复位；
- 文字保持可读，没有持续重叠或闪烁。

### 点击

- 起始帧与原卡片边界完全连续；
- 周围内容退场、选中图抬升、占场、色场和 Reader 显现顺序一致；
- 放大不是均匀缩放，转场中有录屏同类的倾斜、形变和模糊；
- 导航不跳位、不白闪，图片不重新加载；
- 终点是可立即使用的真实 Reader，不是静态详情样板。

### 三道门槛

- 技术：构建、控制台、真实数据、Reader 回调、桌面/手机/键盘/低动态正常；
- 视觉：关键帧叠加与录屏对比完成，差异被明确列出；
- 产品：连续多次打开、阅读、返回仍然顺畅，并由用户做最终接受。
