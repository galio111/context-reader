# Context Reader 中国大陆基础设施选型与成本估算

> 最终状态：已购买并启用腾讯云上海 4 核 4 GB 轻量服务器与 `context-reader.com`，大陆生产迁移已经完成。下表保留为续费/再次迁移时的成本比较；促销价格、库存和资格会变化，不能当作续费承诺。

## 结论

当前已采用的路线是：

- 腾讯云上海 4 核 4 GB、40 GB SSD、3 Mbps、300 GB/月轻量服务器；
- Next.js 应用与 PostgreSQL 17、Auth、REST、Storage 同机容器化部署；
- 当前同机 Storage 保存公开封面、私有附件、错误报告和发音文件，COS/OSS 留作下一阶段异地副本；
- Caddy 提供 HTTPS，systemd 管理健康检查、推荐、备份和恢复校验；
- 通过服务端适配器维持现有 `/api/*` 契约；
- Vercel/Supabase 在验收和观察期内保留为回滚源。

原因不是它绝对最省运维，而是它同时满足“成本低”和“迁移改动小”。现有数据库是 PostgreSQL，包含 UUID、JSONB、事务/RPC、同步游标、CAS 版本和 tombstone 语义。继续使用标准 PostgreSQL，能避免把基础设施迁移扩大为 PostgreSQL → MySQL/文档数据库的产品重写。

迁移时的核心数据库、账号 UUID、权限、用量和协议 2 同步对象已完整导入。31 GB Egress 已确认是首页全量正文读取与高成本预取造成的响应放大；现生产首页只取摘要、正文按意图加载并有五分钟缓存，静态审计会阻止这一问题回归。

## 后端与数据库路线

### A. 同机 PostgreSQL + COS/OSS（推荐）

成本：数据库软件无额外许可费；成本包含在服务器内。COS/OSS 早期通常为 0–3 元/月。

能力：

- 最大程度保留 Supabase PostgreSQL schema；
- UUID、JSONB、唯一约束、事务与现有同步排序可保持；
- 可用 `pg_dump`/`pg_restore` 迁移和恢复；
- 每日备份到异地对象存储；
- 后续可平滑迁移到任何标准 PostgreSQL 托管服务。

责任：需要配置数据库升级、备份、恢复演练、监控、磁盘水位和安全补丁。Codex 可以完成配置、脚本、迁移与验证，但云账号付款、实名、备案验证和密钥授权必须由用户完成。

### B. 腾讯 CloudBase 个人版（一体化候选）

成本：限时 19.9 元/月，约 239 元/年；超额资源可按量计费。

能力：托管 Web/云函数、数据库、身份认证、云存储、CDN 与自动扩缩容；云函数最长可到 900 秒，支持 Web/Next.js 场景。

优点：不用维护 Linux 与 PostgreSQL，早期固定成本低。

缺点：其关系型能力与认证/存储 API 不是 Supabase PostgreSQL/PostgREST/Auth 的原样替代。迁移需要改写数据访问、账号桥接和存储适配，并重新验证事务、用量扣减、同步游标和 Admin 权限。它是“购买更简单”，不是“迁移更简单”。个人版还受资源点/配额约束，若再次出现请求放大仍会超额。

### C. 轻量服务器 + 托管 PostgreSQL

成本：腾讯云 PostgreSQL 2 核 4 GB 中国大陆目录价约 408 元/月（成都约 284 元/月），另计存储及可能的额外备份；再加应用服务器。

能力：一主一备、高可用、自动故障切换、自动备份、监控和扩容。

适用时机：开始收费、单机故障不可接受、恢复点要求低于 15 分钟、数据库与 Node 争抢内存，或人工运维成本已经高于托管费。个人调试期不建议购买。

### D. 自托管完整 Supabase（不推荐）

完整 Supabase 还包括 Auth、PostgREST、Storage、网关、Realtime 和日志等组件。它会把一台小服务器变成多服务运维平台，资源、升级和故障排查都高于本项目实际需求。Context Reader 的浏览器本来不直接访问 Supabase，改成服务端 PostgreSQL/Auth/Storage 适配器更轻。

## 无感迁移的实现边界

“无感”定义为用户看到的界面、功能、账号身份和学习数据不变化，不等于把所有基础设施在一个晚上直接替换。

1. 固定迁移基线：先修复 Egress 放大，冻结同一 Git commit，导出 schema、表行数、对象清单、关键哈希与同步游标样本。
2. 大陆影子环境：部署同一构建，不改正式 DNS；第一阶段仍连接 Supabase，只验证 Node、反向代理、AI、TTS、URL 导入和网络。
3. 后端适配层：增加 `supabase | dual | mainland` 模式，浏览器继续调用相同 `/api/*`；基础设施迁移不借机重写当时的主页、`ReaderView`、翻译、生词本或 Anki。迁移完成后的产品 redesign 以最新产品契约为准。
4. PostgreSQL 影子读：新库只读比对，检查每张表的行数、主键、JSON 哈希、最大更新时间、CAS 版本、tombstone 与 opaque cursor。
5. 全量复制：按外键顺序导入，保留所有用户 UUID，不删除 Supabase 数据。
6. Auth 桥接：旧密码继续由 Supabase 验证；用户下次成功登录时在大陆端用安全哈希重新保存同一次输入，签发新的 HttpOnly session。不会记录明文密码或暴露 synthetic email。
7. Storage 双读：先读 COS/OSS，缺失回退 Supabase 并补齐；对象按 key、大小、类型和 SHA-256 校验。
8. 双写与差异队列：主响应不等待副库；副库失败进入持久重试队列。连续 7 天无未解释差异才允许切流。
9. 新域名迁移：登录用户先在旧站完成最终同步，新站登录后恢复；游客/本机数据使用导出导入或一次性迁移码。Cookie、localStorage 和 PWA 不会自然跨域，因此必须显式处理。
10. 灰度与回滚：先开发者账号、再邀请用户；DNS TTL 提前降到 300 秒；Vercel/Supabase 至少保留 30 天只读回滚能力。

由于当前尚未公开且主要由开发者自己使用，迁移可以在备案完成前充分影子验证，不需要把真实用户当迁移试验对象。这会显著降低“无感迁移”的难度。

## 月度成本情景

以下均不包含开发人力，按已修复 Egress 放大、数据库与应用同机、无托管 PostgreSQL计算。

### 仅自己使用和调试

- 服务器摊销：8–80 元/月；
- 域名摊销：4–10 元/月；
- 对象存储与备份：0–3 元/月；
- DeepSeek：1–30 元/月；
- TTS：0–5 元/月；
- 合计：约 **13–128 元/月**。

如果抢到 99–199 元/年的 4 GB 服务器，较现实的个人成本是 **20–60 元/月**；主要变量会从数据库变成 AI 调用。

### 10–50 名邀请测试用户

- 基础设施：20–90 元/月；
- 对象存储/流量：1–10 元/月；
- DeepSeek：20–150 元/月；
- TTS：1–20 元/月；
- 合计：约 **42–270 元/月**。

前提是游客每日十次额度、缓存命中、失败退款、翻译登录门槛与并发限制继续生效。

### 100–500 名注册用户的小型公开 Beta

- 服务器：80–230 元/月，视并发决定是否升级 4 核 8 GB；
- 数据库：仍可同机为 0 元额外费用，或升级托管 PostgreSQL 增加约 284–408+ 元/月；
- 对象存储与流量：10–80 元/月；
- DeepSeek：100–1000+ 元/月；
- TTS：10–100 元/月；
- 合计：约 **300–1800 元/月**；若升级托管数据库，则再增加约 300–500 元/月。

这个区间很宽，因为公开 Beta 的最大成本不再是“服务器能不能开机”，而是每个用户每天生成多少次新 AI 内容。最有效的成本控制是修复请求放大、共享安全缓存、配额、并发限制、模型路由和 provider spending cap。

## 购买前验收清单

- 确认云账号是否具有产品首单/新用户活动资格；
- 在付款页核对地域、CPU、内存、磁盘、带宽、月流量、购买时长、续费价和超额流量价；
- 确认实例可用于所选主体备案；
- 不购买 Windows 镜像，选择受支持的 Linux LTS；
- 不购买宝塔等非必要面板；
- 不在付款时自动叠加不需要的付费安全、备份或数据库产品；
- 服务器、对象存储和未来数据库选择同地域；
- 首期只买一台，不直接购买托管 PostgreSQL；
- 在服务器上连续运行 72 小时网络与依赖测试后，才确定最终后端迁移深度。
